# 架构决策记录（ADR）

上游 §15 要求 `docs/adr/`。这里记录**已经做过、且有长期影响**的取舍。

**为什么值得单独成文**：这些决定散落在代码注释与交接文档里时，
后来的改动者看不到"为什么当初这么选"，于是很容易用一个看似合理的改动
把上游明确要求的性质破坏掉——而门禁未必抓得住语义层面的那种破坏。

## 状态取值

| 状态 | 含义 |
| --- | --- |
| **已接受** | 当前生效，改动它需要新 ADR 取代 |
| **已接受（延后）** | 决定是"现在不做"，且有书面依据；不是遗漏 |
| **已接受（临时）** | 因外部依赖未到位而采用的临时形态，解锁后由新 ADR 取代 |
| **已被取代** | 保留供追溯，指向取代它的 ADR |

## 门禁

`tests/infra/test_adr_records.py` 会核对本目录：

- 文件名符合 `NNNN-<kebab>.md`；
- 每篇都有 `状态 / 日期 / 上游依据 / 背景 / 决策 / 后果 / 备选方案与不选的理由`；
- 状态取值在**封闭枚举**内（防止随手写一个新状态让"已接受"失去意义）；
- 编号不重复，且本索引列出了每一篇（防"写了 ADR 但没人找得到"）。

> 判据刻意做成结构性的：造一份格式不合规的 ADR 会被抓，
> 但**内容对不对**仍需人来读——门禁不能替代评审，只能说清"该写的东西写没写"。
