# ADR-0003 · 网络按三类域切分，出域判定只在应用层做

- 状态：**已接受**
- 日期：2026-10-05
- 上游依据：§14「生产容器化、服务独立账户与密钥挂载，**不以全部进程运行 root
  的方式上线**」；「数据库与内部 API 只绑定内网；**后台经 VPN 或企业 SSO 访问**」；
  §9 数据分级 C0–C4；§10 内外接口不同认证受众

## 背景

上游同时要求两件事，而它们**不属于同一层**：

1. **网络边界**：内部 API 只绑内网、外部只暴露该暴露的、容器不以 root 跑；
2. **数据分级与出域治理**：C2 出域需批准、C3/C4 不得出域、所有模型调用与外部
   请求经安全网关治理并留痕。

如果把第 2 条也写进网络配置，就会出现**两处策略口径**——
而两处口径必然分叉，分叉的表现是"网络放过了、应用以为拦了"。

## 决策

**网络层只做连通性，应用层独占策略判定。**

- 三类域（`infra/network/network-acl.yml`）：
  - `frontdoor`：对外（`/api/v1/**`），可出网；
  - `internal`：服务间（`/internal/v1/**`），**`internal: true`**（容器层无默认网关）；
  - `edge-uplink`：中心 ← Edge 受控上行，单独成域——因为 Edge 会**断连**
    （§8.3 断连自治），不能与普通内网共享"长连接"假设。
- 出域只允许 `security-gateway` 一个来源，`denied_by_default: true`；
  但**分级判定仍在** `services/_kernel/governance.py` + `egress_audit.py`。
- ACL 里显式写**反例清单**（三类结构性风险），而不是只写允许列表：
  内部接口不得从 `frontdoor` 可达、内部服务不得直连外网、现场侧不得直调中心内部接口。

## 后果

**好处**

- 出域策略只有一处（应用层），可被门禁直接断言：
  机密等级出域被拒、未知等级被拒而非降级、混合上下文取**最高**级而非首个/平均。
- 网络层即使配错，也不会让 C3/C4 静默出域。

**代价（如实记录）**

- **ACL 是声明，不是强制**：真正生效需要网络层（安全组/iptables/VPN）按本文件落地。
  本机没有 docker，**我没有真实跑过 `docker compose up`**——
  编排文件经过 YAML 解析与结构断言，**不等于容器真的能起来**。
- 生产形态（TLS、反向代理、SSO 入口、密钥挂载）随外部依赖一并冻结。

## 备选方案与不选的理由

| 方案 | 为什么不选 |
| --- | --- |
| 把分级规则也写进 iptables | 两处口径必然分叉；且按数据等级做包过滤不可行（等级在 payload 里，不在包头）。 |
| 单张扁平网络 | 无法表达"内外接口不同受众"；内部接口会与对外接口同域可达。 |
| 只写允许列表 | 允许列表不表达"我们明确禁止了什么"，反例清单才能让评审看出意图。 |
