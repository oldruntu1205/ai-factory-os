# ADR-0004 · 首期认证是服务身份 mock，不假设已有 SSO

- 状态：**已接受（临时）**
- 日期：2026-10-05
- 上游依据：§16.1 外部依赖「身份和批准岗位：**SSO、tenant/factory 边界、
  角色、职责分离、限额**」；§14「后台经 VPN 或企业 SSO 访问」
- 取代条件：外部依赖（SSO / 角色 / 限额）解锁后，由新 ADR 取代本篇

> 状态行只写枚举值，不加说明——它要能被机器读。
> "什么时候会被取代"另起一行，见上。

## 背景

上游把身份与批准岗位列为**外部依赖**——也就是说：SSO 接入方式、角色模型、
职责分离规则、授权限额都由工厂侧决定，当前**没有数据来源**。

而 P0–P4 的语义（跨租户隔离、职责分离、越权拒绝）必须能被验证。
如果因为"没有真 SSO"就跳过这些验证，那等于把最危险的一类缺陷留到最后。

## 决策

用**两个头**表达身份，且明确标注是 mock：

- `Authorization: Bearer <token>` —— **身份凭证**（`_has_identity` 只认它）；
- `X-V3-Identity: <service-account>` —— **租户归属**（`_identity_tenant` 用），
  且必须在该身份的授权集合内。

两者职责不同，**缺一不可**。实测踩过：只发后者 ⇒ 一律 401
「缺少或无效的服务身份凭证」；这一条已写进交接文档与联调记录。

租户**不采信请求自称**：`_identity_tenant` 从受信登记推出，
自称与授权集合不一致时返回一个必然不等的哨兵值。

## 后果

**好处**

- 跨租户隔离、职责分离、越权拒绝在 **mock 身份下就可验证**，
  不依赖外部进度。
- 认证失败的语义是**明确的 401 + 可定位错误码**，而不是静默降级。

**代价（如实记录）**

- **角色/岗位/限额没有数据来源**，因此：
  - 后台批准页的三项检查（管理权与批准权分开、限额内、授权岗位）
    结论记为 `UNKNOWN`，界面显示「待核实」，并**点名缺什么**；
  - 门禁里有一条**诚实性断言**：当前数据条件下，
    **没有任何输入能得出「可决定」**。数据接入后这条必须显式改掉，
    而不是悄悄失效。
- token 是固定串（测试夹具用 `p0-test`），**不是安全边界**；
  同源代理的好处是它只存在于服务端，不会进浏览器页面。
- A01 的"跨租户读取被拒"在 mock 下验证充分；但**真实 SSO 撤销链路未接入**
  （A06 的 gap 里如实写明）。

## 备选方案与不选的理由

| 方案 | 为什么不选 |
| --- | --- |
| 等 SSO 到位再验隔离 | 把最危险的缺陷留到最后；且没有隔离验证，其它语义都建在流沙上。 |
| 自己造一套角色/限额数据 | **编造**。拿不到真实限額就编一个阈值，等于给人"已经管控了"的错觉——比不显示更危险。 |
| 只用一个头（合并凭证与归属） | 两者的信任来源不同（凭证来自认证、归属来自登记），合并后无法表达"身份合法但不代表该租户"。 |
