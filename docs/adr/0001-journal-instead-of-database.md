# ADR-0001 · 运行期用 JSONL journal，不引入数据库

- 状态：**已接受**
- 日期：2026-10-05
- 上游依据：§8「8 个核心应用运行单元」；上游明文——
  「数据库、消息代理、对象存储、模型推理进程、Web 静态资产、渠道插件及 **Edge 节点
  不计入这 8 个核心应用单元**」

## 背景

上游定义了 8 个应用运行单元（security-gateway … trajectory-eval），
并要求「任务只保存编排状态投影，Command 的最终副作用状态归 Transaction」。
但**没有**要求每一个单元都自带数据库。

首期要做的是**把架构的可验证语义立起来**：
命令先持久化后返回 accepted、幂等键原子生效、租约与 fencing、回执驱动成功、
跨进程可见的事实。这些是**语义**要求，不是**存储产品**要求。

## 决策

运行期事实落 **append-only 的 JSONL journal**（`services/_kernel/journal.py`），
根目录由 `V3_STATE_DIR` 指定；写入后 fsync。

- 8 个单元**共享同一个状态目录**，因此跨进程可见
  （命令/回执/任务/审计/Vault 都能被别的单元读到）。
- 每次写入是**追加**，读取是「按 key 取最新」。这天然满足
  「事实追加不可变」与「不允许用 record_version+1 覆盖历史决定」。
- 迁移工具链（`scripts/p2_migrations.py`）与迁移台账**已就绪**，
  面向真实 PostgreSQL 的路径也已写好并可在有 DSN 时执行。

## 后果

**好处**

- 零外部依赖即可起全套集群并**真实验证**语义——
  本项目的门禁因此能跑真实多进程 HTTP 测试，而不是 mock 掉存储。
- 「先持久化后返回 accepted」这条能被**真测**（写盘 + fsync）。
- 审计与证据（`V3_EVIDENCE_DIR`）同源，避免"两套事实"。

**代价（如实记录）**

- **不是生产存储**：单机文件、无并发控制（仅进程内锁）、无备份/恢复演练。
- 真实 PostgreSQL 路径**未在目标库执行过**——本机 5432 是用户的实例，
  我不去动它；A12（目标硬件 + 14 天生产数据）与 A13（备份恢复跨域演练）
  因此处于 `not_covered` / `partial`。
- 「迁移真正在目标库执行」被列为**阻塞项**，随生产库凭据与恢复演练一起解锁。

## 备选方案与不选的理由

| 方案 | 为什么不选 |
| --- | --- |
| 直接上 PostgreSQL | 生产库凭据/主机/备份策略都未定（上游列为外部依赖）。**先接一个猜的库，等于把未验证的东西当已验证。** |
| SQLite 单文件 | 强于 JSONL（有事务），但会引入「看起来像生产存储」的错觉，而它同样不支持多写者与备份演练。宁可让"这是临时存储"一眼可见。 |
| 内存字典 | 连「重启后事实仍在」都测不了，P3 的恢复断言会变成假的。 |
