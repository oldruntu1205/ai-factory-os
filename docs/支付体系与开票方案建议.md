# 支付体系与开票方案建议（第3、4项）

> 适用范围：AI Factory 制造业 AI 员工平台（SaaS）
> 结论先行：
> - **第 3 项（支付体系）**：当前为「模拟支付」，要走向真实收款需按"对公转账兜底 → 聚合支付 → 订阅自动续费"三阶段演进；一期建议先接入对公转账 + 人工确认，同时预留支付网关接口。
> - **第 4 项（开票）**：开票类别固定为**服务费**（本平台为 SaaS 订阅服务，属于"信息技术服务*软件服务费"类目），已落地「开票信息维护 → 申请开票 → 财务开具/驳回 → 发票号回填」完整闭环。
> - **已落地（2026-08-18 第二批）**：对公转账支付全流程（付款账号展示/复制、凭证上传、财务审核、24h 缓冲自动取消）已上线，见第四节。

---

## 一、当前现状（审计结论）

### 1. 支付体系（第一批 → 第二批演进）
- `POST /billing/upgrade`：生成**待支付**账单（已修复：不再未支付即生效 ✅）。
- 第一批 `POST /billing/pay`：**模拟支付**——直接置为已支付并应用套餐，无真实资金流。
- **第二批（本批已上线）**：`POST /billing/pay` 改为**对公转账凭证提交**——
  - `GET /billing/pay-account` 返回对公收款账户（演示数据，含复制内容）
  - 上传凭证 → 账单 `pending_review`，套餐**立即临时生效（24h 缓冲）**
  - 平台财务核对到账后审核：通过 = 正式生效；驳回 = 套餐回退
  - 24h 缓冲期未获审核 → 定时任务自动取消升级（套餐回退）
- 无退款、无自动续费（后续阶段）。

### 2. 开票体系（第一批已上线）
- 新增 `invoice_requests` 表 + `companies` 开票信息列（抬头/税号/开户行/账号/地址/电话/票种）。
- 企业侧：`/billing/invoice-info`（读写）、`/billing/invoice-request`（申请）、`/billing/invoice-requests`（列表）。
- 平台侧：`/platform/invoice-requests`（财务看板）、`/platform/invoice-requests/{id}/issue`（开具回填发票号）、`.../reject`（驳回）。
- 类别常量 `INVOICE_CATEGORY = "服务费"`，全程展示给客户，避免开票类目歧义。

## 二、第 3 项：客户支付体系建议

### 阶段划分（按投入/风险递增）

| 阶段 | 方案 | 适用 | 投入 | 风险 |
|---|---|---|---|---|
| **P0 现在就能做** | 对公转账 + 人工确认 | 正式收费冷启动，B 端客户习惯对公打款 | 低（2-3 天） | 低 |
| **P1 建议尽快做** | 聚合支付（支付宝/微信扫码） | 线上自助付费主流 | 中（接入 + 商户号） | 中（需企业资质/签约） |
| **P2 规模化后做** | 订阅 + 自动续费 + 用量后付费 | 客户规模上来后的收入稳定性 | 高 | 中（需处理扣款失败/停服策略） |

### P0：对公转账 + 人工确认（**已上线**）
1. 账单详情展示：对公收款账户（户名/开户行/账号）+ 金额 + 账单号（备注栏填写账单号）。**演示数据 + 复制按钮**（`/billing/pay-account`）。
2. 企业提交「转账凭证截图」→ 账单 `pending_review`，**套餐立即临时生效（24h 缓冲）**，客户无缝使用。
3. 平台财务在「财务管理 → 对公转账凭证审核」核对到账：通过 → 套餐正式生效；驳回 → 套餐自动回退。
4. **24h 缓冲自动取消**：`tasks.billing.expire_grace_bills`（Celery beat 每小时）扫描超时未审核账单 → 自动取消升级、回退套餐。
5. **必须限制**：未提交凭证前套餐不生效（现有代码已保证）；待审核账单阻塞重复下单。

### P1：聚合支付（支付宝当面付 / 微信 Native）
- 后端抽象 `PaymentProvider` 接口：`create_payment(bill_no, amount) → pay_url/qr`、`verify_callback()`、`query_status()`。
- 流程：升级 → 生成账单 → 前端展示收款码/跳转支付页 → 支付平台回调 → **验签**（关键安全点：校验签名与金额，防伪造回调）→ 置 paid 生效。
- 建议选型：
  - 支付宝「当面付」+ 微信「Native 支付」：覆盖国内客户，费率 0.6%。
  - 出海 SaaS（如收海外客户）：Stripe / Airwallex（空中云汇）按美元结算。
- 技术要点：
  - 回调幂等（按 bill_no 防重复生效）。
  - 签名验签、金额校验、回调日志留痕。
  - 掉单对账：定时任务拉取支付平台订单与本地 bill 比对。

### P2：订阅与自动续费（规模化后）
- 到期前 7 天预生成续费账单 + 短信/邮件提醒。
- 签约代扣（支付宝周期扣款 / 微信委托代扣）实现自动续费。
- 续费失败策略：宽限期（如 7 天）→ 降级 starter 只读 → 挂起（复用 `suspend`）。

### 其他建议（通用）
- **优惠/折扣**：`promo_code` 字段挂到 bill，财务可核销；避免直接改价格。
- **退款**：Bill 增加 `refunded` 状态（模型已预留注释），退款走财务线下原路退回 + 状态标记，暂不做系统级自动退款。
- **账单导出**：平台财务导出 CSV/Excel 对账。
- **合规**：真实收款需以持证主体签约；平台侧建议用「平台收款 + 平台开票」模式，避免二清。

## 三、第 4 项：开票方案（类别：服务费）

### 1. 开票类目依据
- 平台提供 SaaS 订阅服务（AI 员工、对话、知识库、报价、渠道等），属于**软件及信息服务**。
- 增值税类目：`信息技术服务 * 软件服务费`（税收分类编码 304020102 附近；各地税局表述略有差异）。
- 平台侧统一按**服务费**开具并展示给客户（代码 `INVOICE_CATEGORY = "服务费"`），与合同表述一致，避免"咨询费/技术服务费"等易被质疑的类目。

### 2. 票种建议
| 票种 | 适用客户 | 税率 | 备注 |
|---|---|---|---|
| 增值税电子普通发票 | 绝大多数企业客户 | 6% | 默认选项，即时推送 |
| 增值税电子专用发票 | 一般纳税人客户 | 6% | 需客户提供完整税号/开户行/地址电话，可选 |

### 3. 流程（已落地）
```
客户（套餐与账单页）
 ├─ 维护开票信息：抬头/税号/开户行/账号/注册地址/电话/票种（保存校验抬头+税号必填）
 ├─ 已支付账单 → 点击「申请开票」（同一账单不可重复申请；未支付不可申请）
 └─ 申请状态可见：待开票 → 已开票（含发票号）/ 已驳回（含原因）

平台财务（平台管理 → 财务管理）
 ├─ 开票申请管理列表（申请单号/企业/账单/金额/抬头/税号/票种/状态）
 ├─ 线下开具电子发票 → 填发票号 → 「已开」回填
 ├─ 信息有误 → 「驳回」并填原因（客户侧可见）
 └─ 全流程审计日志（billing.invoice_request / finance.invoice_issue / invoice_reject）
```

### 4. 电子发票自动开具（**已上线，演示模式**）
- **发票平台抽象层** `utils/invoice_provider.py`：`get_provider(provider)` 工厂 + 可插拔 Provider
  - `mock`（默认）：本地 reportlab 生成 PDF 演示发票（含销售方/购买方/金额明细），不产生真实税务发票
  - `baiwang`（百望云）/ `nuonuo`（诺诺发票）：**逻辑骨架已就绪**，凭据从平台配置读取，未配置时明确报错提示先配置；真实 API 接入点已注释（TODO 标记）
- **平台配置**：`site_contents.invoice_config`（provider + 销售方名称/税号/银行 + API 凭据），财务页「发票平台设置」维护（密钥脱敏展示、留空保持不变）
- **自动开票**：财务页「⚡ 自动开票」→ 调 Provider 开具 → 回填发票号 + PDF 链接（存 `uploads/site/invoices/`，经 `/static/site/invoices/` 下载）；客户侧账单历史与开票申请记录均可下载电子发票 PDF
- **状态闭环**：`pending → issued（发票号+PDF+平台+流水号）`；已开具不可重复开票
