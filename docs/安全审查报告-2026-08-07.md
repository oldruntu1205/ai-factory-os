# 制造业 AI 员工平台 —— 全量代码安全审查报告

> 审查日期：2026-08-07
> 审查范围：backend/（19 个路由模块 + auth + hermes + channels）+ frontend/src
> 审查维度：认证授权 / 多租户隔离 / 文件上传 / 注入风险 / 业务逻辑 / 前端安全

---

## 一、总体结论

多租户隔离整体设计良好（绝大多数业务 API 都经过 `require_company` 校验），但存在 **2 个 P0 级业务漏洞（演示版设计但必须标注生产风险）、8 个 P1 级安全隐患、5 个 P2、4 个 P3**。平台当前定位为演示/MVP 可运行，但**若直接部署生产必须修复 P0/P1**。

## 二、问题清单（按严重程度）

### 🔴 P0 —— 严重（生产必须修复）

| # | 位置 | 问题 | 风险 |
|---|------|------|------|
| 1 | `api/billing.py:122` `/billing/upgrade` | **套餐未支付即生效**：`c.plan = data.plan` 直接更新企业套餐，账单仅生成 `unpaid` 状态。客户可不付款免费升级 Enterprise（50 AI 员工/100 万对话） | 收入损失 |

| 3 | `api/account.py:66` `/account/send-code` | **验证码直接明文返回前端**：`"mock_code": SMS_MOCK_CODE`，等于"验证码=公开"，手机验证形同虚设 | 任意改密（配合固定码 123456） |

## 三、做得好的地方（亮点）

- ✅ **多租户隔离执行到位**：`agent / crm / knowledge / quotation / leads / dashboard / members / system` 全部 `require_company` 校验 + 查询带 company_id 过滤
- ✅ **知识库上传**：`knowledge/upload.py` 有扩展名白名单 + 大小限制（413）+ UUID 随机文件名防路径穿越
- ✅ **平台超管隔离**：`_require_platform` 严格校验角色，企业账号访问财务/统计接口返回 403（已实测）
- ✅ **RBAC**：Hermes 权限系统双重校验（manifest 声明 + 租户权限点）
- ✅ **Webhook 签名**：WhatsApp 支持 `X-Hub-Signature-256` HMAC 校验（hmac.compare_digest 正确用法）
- ✅ **密码存储**：bcrypt 哈希，无明文
- ✅ **前端**：无 dangerouslySetInnerHTML（无直接 XSS），认证拦截器统一处理 401
- ✅ **审计日志**：登录/邀请/改密/角色变更均有操作日志

## 四、修复建议（按优先级）

### 立即修复（上线前必须）
1. **billing**：升级改为「先支付后生效」——`upgrade` 只生成 unpaid 账单，`pay` 成功后才更新 `c.plan`；`pay` 需接入真实支付网关回调验签
2. **SECRET_KEY**：强制从环境变量读取，无配置则启动失败（fail-fast），不提供默认值
3. **验证码**：删除 `mock_code` 明文返回；接入真实短信服务（阿里云/腾讯云 SMS）
4. **登录限流**：按 IP+账号 5 次/分钟，超限锁定；统一错误文案
5. **email/bounce 越权**：`filter(EmailLog.company_id == current["company_id"])`
6. **wecom/robot/send**：加认证（Bearer token 或内网白名单）
7. **license 上传**：加大小检查（读取前先看 Content-Length）+ content-type/magic bytes 校验
8. **补 .gitignore**：排除 `.env`、`*.db`、`uploads/`、`node_modules/`、`dist/`

### 尽快修复
9. hermes session 校验：`/hermes/memory/short`、`/hermes/tool/call` 校验 session 归属企业
10. quotation customer_id 归属校验
11. 邮件发送限流（每企业每日上限）
12. WhatsApp/企微 webhook 在无密钥配置时直接拒绝（或强制要求配置）
13. JWT 支持注销/黑名单，token 有效期缩至 24h

### 后续优化
14. 套餐升级增加防降级逻辑与冷却期
15. LLM 输出解析加类型兜底
16. 邮件日志补 company_id
