## 3. 发布状态机与重开门禁

**DRAFT → SCHEMA_FROZEN → CALIBRATED → SHADOW → APPROVED → ACTIVE → REVOKED**

| 正常转换 | 必须查验的可信证据 | P4 限制 |
| --- | --- | --- |
| DRAFT → SCHEMA_FROZEN | 工艺/设备共同审定的输入/输出、单位、范围、枚举、缺失处理、动作映射及版本/hash | 不写设备 |
| SCHEMA_FROZEN → CALIBRATED | 按时间/批次隔离训练/校准/测试，独立测试集与任务级指标通过 | 不写设备 |
| CALIBRATED → SHADOW | Schema 与离线验证有效；门槛已冻结；现场采集许可与物理/网络禁写证据有效 | 无真实副作用 |
| SHADOW → APPROVED | 至少14天连续生产比对、冻结工况/偏差/延迟/误判全部达标，现场批准有效 | 两周期满不自动批准；P4 未冻结依赖时不得晋级 |
| APPROVED → ACTIVE | 签名许可、白名单/边界、互锁、现场批准、回退/回滚演练及 P3 副作用门禁全部通过 | P4 新接口仍无执行权；真实启用属于后续阶段及既有 activate 门禁 |
| ACTIVE → REVOKED | 可信撤销证据与现场同步；禁用 AI 新动作 | REVOKED 无可执行处置，无出边 |

状态台账必须 CAS `expected_version` 与权威来源对齐。跳态/逆行拒绝；P4 只能记录后续七态的证据，不能借台账设置 ACTIVE 开控制口。撤回批准及紧急停止是安全权限的即时失效，不依赖完成正常晋级链，也不引入新 release 状态；设备安全始终优先。

| 影响行为的变更 | 重开门禁表达 | 必须失效/重做 |
| --- | --- | --- |
| 模型 | 新行为包创建替代 DRAFT；原包不可原位替换 | 旧批准失效；对应离线验证/独立校准与新影子门禁 |
| Schema | 替代 DRAFT，`schema_freeze_required=true` | 重新 Schema 审定，再离线验证/校准及影子 |
| 特征提取器 | 替代 DRAFT，重新确认特征/输入规格 | 对应 Schema 冻结、离线验证/校准及影子 |
| tokenizer | 替代 DRAFT，重新确认输入/输出解释及版本绑定 | 对应 Schema 冻结、离线验证/校准及影子 |
| 校准参数 | 替代 DRAFT，门槛与校准包重新绑定 | 旧批准失效；对应离线验证/校准及影子 |
| 动作映射 | 替代 DRAFT，`schema_freeze_required=true` | 重新审定映射、设备/参数范围，离线验证/校准及影子 |

`gate-reopen` 的 `{release_id}` 必须等于 `previous_release_id`；replacement ID 必须不同，并绑定不同的可信行为包。选择新 DRAFT 是保守的门禁载体，不是旧 release 的逆向转换；旧 release 保留历史，批准必须即时失效并同步现场禁用新动作。差异归因及是否影响行为由可信工程评审决定，不能由模型自报，也不能只换文件沿用旧批准。非行为变化只有审定证据明确证明后才可复用未受影响证据；不允许复用已受影响的离线/影子批准。

## 4. Guard 判定顺序

结果 `checks` 是长度恰为9的固定 tuple；每项包含固定 stage、`passed`、证据引用/hash。`first_rejection` 必须是按优先级找到的第一个失败项。未知、不可判断、证据失效、依赖不可用一律按失败处理；可记录后续诊断，但不能因后续通过改变首个拒绝理由或执行权限。

| 顺位 / stage | 必须检查 | 谁优先于谁 / 不可覆盖项 |
| --- | --- | --- |
| 1 / structure | 缺失字段、NaN/非有限数、越界、单位不明、Schema/领域约束 | 优先于2–9；人工批准、置信度均不可覆盖 |
| 2 / freshness_timeout | 采样新鲜度、deadline、特征/推理/协议端到端超时 | 优先于3–9；高置信不能救回过期输入 |
| 3 / ood_drift | 工况在适用域，无异常漂移 | 优先于4–9；不能用高置信解释 OOD |
| 4 / version | 模型/Schema/特征/tokenizer/校准参数/动作映射版本与 hash 绑定一致，校准包有效 | 优先于5–9；旧批准不能覆盖包变化 |
| 5 / permit_policy | 本地策略及许可签名有效、未过期、适用范围正确 | 优先于6–9；中心可达或人工在线不替代本地许可 |
| 6 / device_parameter_allowlist | 设备许可、动作白名单、参数边界及注册目录 | 优先于7–9；开放文本/未知设备或动作拒绝 |
| 7 / interlock | 现场互锁、安全 PLC、急停、硬件安全信号 | 优先于8–9；**有效人工批准也不能覆盖硬互锁** |
| 8 / budget | 本地执行预算未超限 | 优先于9；置信度不增加预算 |
| 9 / confidence | 独立数据校准的任务级指标及场景冻结聚合算法/阈值 | 只能在前项通过后参与候选判定，无提权能力 |

设备权限、安全 PLC、急停与联锁的强制安全优先级始终高于 AI/人工批准；表内的诊断顺序不能延迟或绕过硬件安全制动。Guard 不接受 LLM 自报数字，校准不可用时 confidence 显式 null 且拒绝候选。多字段算法必须在场景规格声明算法引用/版本/hash、字段顺序、缺失规则、字段依赖、独立校准数据集及任务指标；不预设平均、乘积或取最小值。

自动执行的必要条件仍为 §8.2 的全部合取：**闭环模式、校准包有效、Schema 通过、工况在适用域、输入新鲜、无异常漂移、签名本地策略未过期、设备/参数在许可范围、互锁通过、执行预算未超限**，加上场景有效批准及设备权限。P4 固定 shadow，闭环条件始终不成立。`candidate_eligible` 只用于影子比对资格，不是自动执行许可；`execution_allowed=false`、`ai_new_actions_enabled=false`、`comparison_only=true`，结果对象无动作/设备参数/执行凭据字段，任何扩展字段被 Schema 拒绝。

失败必须显式拒绝候选、禁用 AI 新动作、保持/回到设备基线并留下持久化人工处理证据，不可静默丢弃、返回成功动作或向公网降级。HMI 只提供复核入口，不能给结构错误或硬互锁发例外许可。

## 5. Shadow 门槛与连续14天口径

`p4-shadow.json` 的 Threshold 与 Report 完全分离。Threshold 包含事先审定的门槛值、冻结时间、冻结人证据、hash、场景/行为包/校准包/硬件及统计规格引用。Report 只保存实测、阈值引用/hash和覆盖缺口；不允许嵌入 threshold、事后修改阈值或自己定义“通过”。Evaluation 由 trajectory-eval 查两个可信记录，全部检查通过才可 `passed=true`，始终 `automatic_approval=false`。

| 冻结内容 | 报告实测 | 口径及判定 |
| --- | --- | --- |
| 最低连续观察时间，至少1209600秒 | UTC 起止、连续观察秒数、生产比对记录引用/hash | 至少14×24小时连续观察；按原始记录验证，不用14个日期标签代替连续时间 |
| 预先列明工况、每工况最低样本、覆盖率 | 各工况样本计数、来源、覆盖率及缺口 | 现场生产条件比对；工况不足延长，无样本工况不能算通过 |
| 偏差指标定义、单位、最大偏差 | 同指标同单位实测偏差 | 冻结对照基线及计算方法；禁止更换分母/单位/计算方法逃避超标 |
| 目标硬件、端到端 p50/p95/p99 上限及超时率 | 特征、排队、推理、校验、只读协议往返与端到端分位、超时率 | p50≤p95≤p99；按采样链求端到端分位，不相加各段分位；设备写往返不可在 P4 测量 |
| 校准包、误判/拒绝指标及上限 | FP/FN计数、对应分母与率、拒绝率、样本量 | 指标、标签来源、风险定义及独立数据规则事先冻结；率与计数核对 |
| 禁写机制与观察证据 | physical/network/physical_and_network、证据引用、真实副作用数为0 | 物理断开或网络 ACL 禁写必须有效；软件布尔开关、低概率写均不合格 |

冻结必须严格早于 `started_at`。门槛、场景、行为包、校准包、统计规格和目标硬件的 hash 必须匹配；不得混用旧发布的报告。行为性变化重新开始对应离线及影子门禁，不跨包拼接观察时间。重启、数据缺口或生产中断应记录；连续性是否满足按事先冻结采样/工况计划判定，无法证明连续则不通过并重新/延长观察，不能拼接两个不足窗口充当连续14天。

协议往返仅可为采集/只读状态查询；不适用时分位显式 null 并保留审定口径，不能填0伪装已测。冻结性能时限不得要求通过真实设备写来获取 P4 样本。任何写尝试、失效 ACL 或真实副作用均形成拒绝证据，即使没有成功写入，也不能当作合格禁写证明。

## 6. 本地 spool 与重连规则

事件必须持久化 `context`、`edge_id/boot_id/sequence/event_id`、发生时间、aggregate 引用/版本、事件及 payload hash、受控内容引用。类别 comparison / executed_fact / pending_action 是记录类别，不是新增设备命令生命周期。已执行事实必须带命令幂等键、动作回执引用/hash。待执行记录必须带 `issued_at/expires_at/ttl_seconds`；P4 不执行它。

| 情况 | 处理 | 可观察约束 |
| --- | --- | --- |
| 首次事件 | 校验租户/edge/证据，持久化事实后逐事件 ACK | 不能先 ACK 后落盘；本地未收到可信 ACK 前保留记录 |
| 相同 event_id、相同 hash | 租户+edge 范围内去重，返回同一事实引用 | 不生成第二条事实或动作，`duplicate=true/state_updated=false` |
| 相同 event_id、不同 hash | 409 冲突，保留本地记录及冲突证据 | 不覆盖既有事实，不当成功 |
| sequence/boot 重启 | sequence 在 tenant+edge+boot 内单调；boot 变化不能清除 event_id 去重台账 | 不因重启重复动作或丢失事实 |
| 已执行设备动作 | 只补报事实及回执 | `center_execution_allowed=false`；无中心重放接口，重放要求/额外命令字段拒绝 |
| 历史 pending_action | 补报待执行引用的历史事实，绝不使补报成为执行请求 | 本地后续阶段在执行点再查 TTL/许可/版本/互锁/预算；P4 始终无执行 |
| now ≥ expires_at | 过期动作不得执行，显式记录过期及收敛结果 | `expires_at=issued_at+ttl_seconds` 经可信时间核对，不依赖中心响应 |
| 迟到/乱序 | 比较 aggregate_version，版本≤当前版本不更新投影 | 保存历史事实；`late=true/state_updated=false`；不能按跨 boot sequence 直接判新旧 |
| 部分批次失败/ACK丢失 | 按每 event_id 处理；只移除已确认事件，未确认同 ID/hash 重报或查询 | 不整个批次标成功、不静默丢弃、不重复设备动作 |
| 指令及回执重复 | tenant+edge+device 下独立幂等键/hash及本地状态确认 | 同键同内容返回同一结果、同键异内容409；不重复副作用 |
| 指令已发但回执丢失 | 复用 §12 UNKNOWN/人工收敛语义，先查设备状态 | 不换键重发；不能把超时等同“未执行”；中心只接收事实 |

去重/迟到/TTL/hash相等/持久化 ACK 属跨记录及时间语义，由 L2 实施、L3 故障注入。Schema 只能拒绝危险记录形态及矛盾字段，不能证明 fsync、时钟、设备状态或并发隔离。补报事件与设备执行命令必须保持不同受众、入口、调用权及 owner 边界。

## 7. 断连自治决策表

以下 restricted 行声明 §8.3 必要约束，属于后续阶段，不授权 P4 设备动作。P4 新接口只接受 shadow、只返回 ShadowDecision。

| 模式/条件 | AI 新动作 | 现场处置 |
| --- | --- | --- |
| shadow，中心连接或断开，许可全部有效 | 禁用 | 继续获准的采集/推理/比对及 spool；维持设备基线 |
| 已 APPROVED/ACTIVE 的场景，在后续 restricted 模式下断连；有效签名策略和许可、匹配版本、可用持久化、现场规程及全部 Guard/互锁/预算通过 | 只有 ACTIVE 且实际启用时可按许可和现场规程自治 | 本地安全决策不依赖中心人工及时响应；APPROVED 本身不开放执行 |
| 策略或许可过期/签名无效 | 禁用 | 回到设备基线，按固定回退定义与现场规程处理并留人工证据 |
| 模型/Schema/特征/tokenizer/校准/动作映射版本异常 | 禁用 | 回设备基线、旧批准失效，重开对应门禁 |
| 本地持久化不可用/容量耗尽/无法持久化审计意图 | 禁用 | 回设备基线；禁止继续新动作并等待中心补证 |
| 工况 OOD/漂移、互锁拒绝、预算超限或无法确认输入 | 禁用 | Guard 显式拒绝；硬安全控制优先，记录/人工收敛 |
| REVOKED 或场景无有效批准 | 禁用 | 基线及现场安全控制；不等待中心撤销响应再停新动作 |

所有有效期边界按可信 UTC 校验：`now >= valid_until` 即失效。网络断连本身不能提升权限。签名有效、策略未过期的字段声明必须与本地可信签名验证及缓存注册版本一致；失败时无法持久化事件也不能导致继续动作，现场安全仍独立维持。

## 8. 安全回退动作表（逐设备定义）

不编造实际设备、协议或参数。每个定义必须绑定租户、工厂、`device_ref`、版本/hash、设备工程师审定证据、触发条件、基线、参数边界、互锁及现场规程。具体设备逐行由设备工程师填实；模型不能选用或创造动作。

| 设备绑定 | 固定动作（原文枚举） | 定义责任与依赖 | P4 行为 |
| --- | --- | --- | --- |
| 逐设备 device_ref，待冻结 | 保持基线 | 设备工程师冻结该设备正常基线及触发规格 | 禁用 AI 写入，记录所绑定定义及比对 |
| 逐设备 device_ref，待冻结 | 停止自动调参 | 设备工程师冻结停止范围及现场接管规程 | 既有现场机制维持，不由影子 AI 发控制指令 |
| 逐设备 device_ref，待冻结 | 降速 | 设备工程师冻结目标边界、互锁及安全规程 | 仅记录固定定义；真实设备动作依现场已有控制 |
| 逐设备 device_ref，待冻结 | 受控停机 | 设备工程师冻结停机步骤、安全 PLC/联锁与恢复规程 | 仅记录固定定义；不创建影子停机写路径 |

查不到设备定义/hash不符时禁用 AI 新动作、回既有设备基线并进入人工队列。模型提供即兴回退、设备通配、跨设备复用未经审定定义均拒绝。安全 PLC/急停动作从不受影子 AI 批准或等待队列控制。

## 9. L2 实现约束清单

### 必须

- 仅读取既有冻结契约，新增契约单独登记；OpenAPI 与 schemas 两侧均不得漏登。保持 nested Context、既有认证受众、统一 Error、L0–L5 及既有 owner 边界。
- P4 现场控制写口物理/网络禁用；推理、Guard、回退、断连与 spool 各路径均不能写设备。模型没有设备寄存器、凭据或业务提交权限；中心快链不写设备。
- 按固定九级顺序生成可信检查结果，结构及硬互锁不可被人工批准或高置信覆盖；所有自动候选条件合取，P4 无闭环执行。
- 版本与 hash 锁定六类行为组件；变化撤销旧批准并创建新门禁载体；不得替换文件继续旧批准。正常晋级只能相邻，REVOKED 禁执行。
- 冻结门槛严格早于观察开始；报告只提交实测，服务对真实记录计算晋级；不足14天或工况不足明确失败并延长，不能自动批准。
- 本地持久化 spool、事件去重、指令/回执幂等与状态确认；已执行事实只补报；TTL、迟到保护及 ACK 后删除要在本地执行。
- 策略/许可失效、版本异常、持久化不可用禁用 AI 新动作并回设备基线；控制安全不依赖中心人工及时响应。固定回退逐设备审定。
- 敏感正文不出现在契约示例/日志/请求或报告内，仅用受控引用/hash；禁止真实域名、账号、密钥与内网地址示例。时间统一 UTC Z。
- 将 `tests/contracts/test_p4_contracts.py` 纳入正式 p4 阶段门禁；先静态契约再现场语义/运行验收，送审记录 Mock/sandbox/真实环境、命令、版本、退出码与脱敏证据。

### 建议基线

- 本地单写入序列、持久化事务/WAL、按事件 ACK 和容量监控；具体持久化介质通过 ADR 冻结，缓存不得承担可靠性。
- 签名包与门槛不可变登记；发布台账 CAS，与本地激活包/hash保持可核对投影；观察链路输出硬件 manifest 和分段/端到端指标。
- 用可控时钟和断连/重启/回执丢失注入开展 Mock 验收，再在现场采集许可下完成连续真实生产报告。Mock 准确率与短时性能不能替代真实影子证据。
