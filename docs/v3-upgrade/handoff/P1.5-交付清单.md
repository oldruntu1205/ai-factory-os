## 0. 为什么插了这个阶段

P2「数据孤岛闭环」的真实阻塞是**外部依赖**（ERP/PMC/MES/WMS 的产品版本、API 授权、
字段与单位映射），没有输入就不能做、更不得编造。但 P2 的交付物里有两项与外部字段无关
且当时**完全缺失**：

1. **单一真相源**：P1 结束时 Task 存在性有两份事实（control-plane 的状态 + 另行写的"任务投影"）；
2. **事件一致性层**：`outbox`/`inbox`/版本收敛/DLQ 在 P0/P1 都是**零实现**。

这两项都是 P2/P3 的前置，且能完全在本地验证。因此作为 P1.5 先行落地。

## 3. 本阶段实际修掉的实现缺陷（都是实测发现的）

| 缺陷 | 发现方式 | 修法 |
| --- | --- | --- |
| **两个真相源**：Task 状态在内存、另写一份投影 journal 给消费方 | P1 遗留观察 | Task/Run/Approval/Command 统一以 journal 为唯一真相源，内存仅作请求内缓存 |
| **内存缓存陈旧**：其它进程改了 journal，本进程内存仍是旧值，守卫读到旧状态而放行 | P1.5 用例失败（UNKNOWN 守卫失效） | `_find` 改为**每次从 journal 读**，缓存不再优先 |
| 版本基线错误：从未应用过时按 0 起算，导致从 v1 开始的合法流永远判"缺版本" | 事件内核自测 | 基线改为 **-1** |
| **缺版本事件被记入 inbox**：补拉回来后会被当成"已见过"，永远无法应用 | 事件内核自测 | 缺版本只进补拉队列，**不写 applied 记录** |
| 校验顺序错误：用途未登记时先报"身份未验证"，掩盖真实原因 | P1.5 用例失败 | 先判用途登记，再判身份/范围 |
| 日历非法时间被放行：`2026-13-45T99:99:99Z` 能通过契约 pattern | P1.5 契约用例 | 内核加**日历真实性**校验（比契约更严，属加严非违约） |
| DLQ 里的事件结构非法（契约要求 `event` 是合法 Envelope） | P1.5 运行验收 | 增加 `sanitize_envelope`：能取到的原值保留，取不到的用**明确占位**，绝不编造业务值 |
| 事件处理异常直接抛 500（应进 DLQ） | P1.5 运行验收 | 接收与重放路径都捕获 `EventError` → DLQ |

## 4. 门禁可信度（变异测试，实测输出）

| 阶段 | 变异数 | 结果 |
| --- | --- | --- |
| P1 | 6 | ✅ 全部捕获 |
| P1.5 | 7 | ✅ 全部捕获（去重/迟到/缺版本/回执哈希/UNKNOWN/权威读租户隔离/outbox 原子性） |

**变异脚本自身也发现并修正了两个 bug**（比漏检更危险的是**假证据**）：

- **行尾失配静默不生效**：脚本用 `str.replace` 注入多行原文，而源文件是 LF、脚本里的
  多行字符串带隐式行尾差异 → 替换**不生效**，脚本却把"测试仍通过"当成"已捕获"。
  已改为先归一化行尾再替换，并新增 `[无效]` 判定：原文未命中即视为失败（不可当作通过）。
- **变异目标测试选错**：outbox 原子性变异原指向 `test_nothing_staged_produces_no_side_effect`，
  该用例根本不覆盖原子性 → 注入后仍通过，被误报为"逃逸"。已改指
  `test_state_and_event_commit_together`。

另有 **2 个真实门禁盲区**由变异暴露并已补用例：跨 owner 权威读的租户隔离、
outbox 原子性的落盘形态断言。

## 5. 已知限制（**不得**当成已实现）

1. **不是真事务**：outbox 原子性靠同目录 `os.replace` 模拟；生产应为"状态表与 outbox 表同一 DB 事务"（P2/P3）。
2. **无 broker**：没有真实消息代理与订阅配置；"至少一次投递"目前由调用方重投体现。
3. **补拉队列只是记录**：`backfill` 记录了缺版本事实，没有真实的补拉调度器与超时。
4. **DLQ 无重试策略**：只有人工重放入口，没有自动重试、退避与次数上限策略。
5. **无跨库事务**：按契约只做本 owner 原子提交；跨 owner 用事件引用（这是设计，不是缺陷）。
6. **receipt 不做签验**：`authority_verified` 恒为 true；真实签名/凭证校验待冻结。
7. **posting_status 恒为 NOT_CONFIRMED**：业务成功≠账务过账，真实过账回执待 ERP 接入。
8. **P0/P1 的"两个真相源"绕过已删除**，但**真实 DB 的 owner 隔离（schema/role/RLS）仍未落地**。
9. **`backend/`（V2.1 在产单体）一行未改**。
