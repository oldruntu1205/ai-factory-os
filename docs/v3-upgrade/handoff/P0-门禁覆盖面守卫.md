- 日期：2026-10-05

- 判据：`scripts/gate.py --stages p0,p1,p15,p2,p3,p4,assertions` **exit 0**（1380 用例）；
  变异 **160 个可捕获项全捕获**

## 一、⚠️ 先更正上一轮的错误结论

上一轮我写了「`test_contract_inventory_gates.py` **从未被门禁覆盖**」，并据此加了一步。
**这个结论是错的**，本轮用**对照实验**推翻：

门禁里**早就有**反向覆盖机制（`gate.py` 的 `_unreferenced_contract_tests()`），
会把未被任何步骤显式引用的契约测试**自动补进 assertions 阶段**。
门禁输出里确实有：

```
## 契约未引用测试：tests/contracts/test_contract_inventory_gates.py
```

**它一直在被跑。** 我手工加的那一步是冗余的，**已撤除**。

**我错在哪**：只读了门禁的**显式步骤清单**，没读清单**之后的扩展代码**，
就把「清单里没有」当成了「从来没跑」。

> **这是"只看半段代码就下结论"。** 更正已写进上一轮文档的开头（原文保留作追溯）。

## 二、但对照实验暴露了一个**真缺口**

普查结果：

| 位置 | 文件数 | 门禁覆盖情况 |
| --- | --- | --- |
| `tests/`（19 个目录） | — | **全部**被覆盖（显式引用或反向覆盖） |
| `backend/tests/` | **7** | 只显式引用 **1** 个（`test_hermes_mcp_scheduler_audit.py`） |

**`backend/tests/` 不在反向覆盖的扫描面内**（反向覆盖只扫 `tests/`）。
所以其余 **6 个**文件：**没被跑，也没有任何地方记录"为什么不跑"**。

那 6 个属 **V2.1 后端**，需要 FastAPI TestClient、**RabbitMQ**、**真实 DeepSeek API key**、
真实数据库——**不跑它们是对的**（把需要外网凭据的测试放进门禁，会让门禁在离线环境**假红**）。

**但「不跑」与「明确记为不跑」是两件事**：

> 前者是**静默跳过**，后者是**可核对的决定**。

## 三、本轮做了什么

新增 `tests/infra/test_gate_coverage.py`（5 条）：

| 用例 | 断言 |
| --- | --- |
| **无测试文件被静默跳过** | 每个测试文件要么被门禁引用、要么在豁免表里 |
| 豁免不得过期 | 豁免的文件必须**确实存在** |
| 豁免必须写理由 | 理由长度下限（防"只列文件名"） |
| **能力自证 + 路标** | 证明 `backend/tests/` **确实不在**反向覆盖扫描面内；哪天扩到了，本用例失败，提醒"豁免表可退休" |
| **豁免表不得是垃圾桶** | 豁免数必须**小于**该目录测试文件总数——整目录豁免等于没做逐个判断 |

豁免表逐条写明理由（V2.1 在产依赖 / 需要外网凭据 / 需要 broker / 归属别的验收面）。

**否定验证**：把 `test_marketplace.py` 移出豁免表 ⇒ **立即报红**（实测通过）。

## 五、已知限制

1. **豁免表是人工维护的**：新出现的 `backend/tests/*.py` 仍需要人来判断，
   守卫只能保证"不会静默跳过"（会报红要求二选一）。
2. **只覆盖测试文件**：`scripts/`、`tools/` 下的辅助脚本（如 `mutate.py`、`preflight_deploy.py`）
   有没有被执行过，本守卫不管——那是另一类缺口。
3. **`backend/tests` 里那 6 个文件**仍然**没有**在 V3.0 门禁里跑过；
   本轮只是把这个决定**记录下来**，没有把它们跑起来（跑起来需要外部依赖，会假红）。
4. 员工页/对账/发布三页已完成；`edge/` 独立部署树未建（ADR-0006 有意延后）；
