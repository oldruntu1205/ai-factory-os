## 一、补上上一轮我自己记下的另一处重复实现

上一轮末尾我写下了这条已知限制：

> 只覆盖发布状态机这一处跨语言判据。`apps/` 里其它"界面自算"的东西
> （如 `escapeHtml` 在页面与 `view.js` 各有一份）**未纳入**。

本轮把它纳入。**转义是安全相邻的实现**——分叉意味着"某一侧少转一个字符"，
而那一侧可能正在渲染不可信内容（`release_id`、错误消息、审批说明）。

## 二、⚠️ 实测到的真实分叉

两份实现都替换 `& < > " '` 五个字符，看起来一样。但用 `node` 真跑两侧后发现：

| 输入 | `view.js::escapeHtml` | 页面 `esc` |
| --- | --- | --- |
| `null` | `"null"` | `""` |
| `undefined` | `"undefined"` | `""` |

**根因**：页面的 `esc` 写的是 `String(value ?? "")`，`view.js` 那份写的是 `String(value)`。

**后果**：页面把缺失值渲染成空白，`view.js` 渲染成**字面量 `"null"`**——
用户会在表格里看到 `null` 这五个字符。

**严重性诚实评估**：两者**都做了转义**，所以**不是 XSS**；是显示缺陷。
但**行为不一致本身就说明它没被设计过**——哪份先写对算哪份。

**修法**：`view.js` 对齐成 `String(value ?? "")`，并写明"选 `?? \"\"` 是因为界面语义是
『没有值』"。17 条既有 view 测试全部仍通过。

> **一致性由可执行的门禁来守，而不是靠"我记得两边一样"。**

## 三、⚠️ 顺带抓到的 3 处未转义 `innerHTML` 插值

我加的结构性检查（找 `innerHTML` 里的 `${...}`，确认包了 `esc(`）报出 3 处。
逐条核对后**全部安全**，但**证据强度不同**，所以处理方式也不同：

| 插值 | 为什么安全 | 处理 |
| --- | --- | --- |
| `result.approved ? "通过" : "否决"` | 条件**只选字面量**，但类型保证来自**别处**（`normalizeDecision` 强制布尔） | **改写为 `=== true`**，让"只选字面量"成为**局部可验证**的事实 |
| `writeState` | 值在**构造处**已对唯一数据插值 `esc(...)` 过 | 进豁免表并注明 |
| `parts.join(" ")` | 只含**服务名常量**与拼接字面量 | 进豁免表并注明 |

**第一处的改写是典型取舍**：原来代码**是对的**，但它的正确性需要读者跳到
`approval.js` 才能确认。改成 `=== true` 后，同一个文件里就能看出分支只选字面量。

**豁免表逐条写明理由**，并配一条"豁免不得过期"的断言——
否则豁免表会积累早已不存在的东西，读者再也分不清哪些还是真的在用。

## 四、门禁实现（6 条）

`tests/infra/test_escape_parity.py`：

| 用例 | 断言 |
| --- | --- |
| 五字符替换表一致 | 两份实现对 16 个探针（危险字符/已实体/模板反引号/Unicode/控制字符）结果相同 |
| **能力自证** | `<script>` 必须变 `&lt;script&gt;`、`&` 必须变 `&amp;`、转义后不得再含裸 `<`/`>` —— 否则"两份一致地不转义"也会通过 |
| 缺失值行为一致 | 对应本轮抓到的分叉 |
| `innerHTML` 插值全过 `esc` 或在豁免表 | 注入面 |
| 豁免不得过期 | 防豁免表退化成历史账 |
| 未转义-真值判断不得回退 | 防把 `=== true` 改回去 |

**探针集**刻意包含 `&amp;`（已实体，必须再转义 `&`，否则会二次解析）、
`` ` ``（模板字符串风险字符）、`javascript:alert(1)`、Unicode/emoji。

## 七、已知限制

1. **只覆盖这一个页面**（`apps/web-admin/public/index.html`）。若将来加别的页面
   （员工页/对账页），需要把检查扩展到那些文件。
2. **插值检查是正则的**：它认 `innerHTML = \`...\`` 这一种赋值形态。
   若改用 `insertAdjacentHTML` / DOM API，检查会**漏掉**（不报错，只是不覆盖）。
3. **转义一致 ≠ 完整防护**：属性上下文、URL 上下文需要不同的转义策略，
   本门禁只保证"五字符替换表一致"。当前页面只把转义结果放进元素**内容**位置，
   未用于 `href`/`src`/`on*`；将来若那样用，需要另加检查。
4. 仍未做：**对账页 / 员工页**（§15 要求）；**任务↔命令关联**（如实登记的缺口）。
