## 一、上一轮顺带发现的缺口

上一轮我在交接文档里如实记下：

> `tests/contracts/test_contract_inventory_gates.py` **不在门禁的步骤清单里**，
> 它当前有 28 条失败。这是既有状态，不是本轮引入——但意味着那套元校验**从未被门禁覆盖**。

本轮先**核实**那条记录，结论要修正：

| 我上一轮写的 | 核实结果 |
| --- | --- |
| 「有 28 条失败」 | **不准确**。单独跑是 **28 passed**；那 28 条失败是**次序相关的污染**，不是真缺陷 |
| 「从未被门禁覆盖」 | **准确**，且这是真问题 |

## 二、⚠️ 真相：那 28 条失败是**测试自身不隔离**

`test_contract_inventory_gates.py` 会**直接改模块级字典**：

```python
inventory.CONTRACT_INVENTORY[phase] = {...}   # 合成一个不存在的阶段
```

它靠 pytest 的回滚式 `monkeypatch` 还原；但同一文件里：

```python
UNKNOWN_PHASES = tuple(islice(_unregistered_phases(), 2))   # ← 导入时就算好了
```

`UNKNOWN_PHASES` 在**导入时**求值，依赖"当下有哪些阶段已登记"。
一旦有一次运行泄漏了状态（我调试时先删了清单条目再跑），它就会把**已经存在**的阶段
当成"未登记阶段"。

**实测**：同一份代码，一次运行 `28 passed`，另一次 `28 failed`。

> **次序相关的测试比没测试更危险——它会教人忽略红灯。**

## 三、本轮做了什么

### ① 新增隔离守卫（3 条）

`tests/infra/test_contract_inventory_isolation.py`：

| 用例 | 断言 |
| --- | --- |
| **能力自证** | 同进程内的改动**必须可见**（证明"快照对比"不是空转）；子进程的改动**必须不可见** |
| 无合成阶段残留 | 清单里不得留 `*-probe` / `*-future` |
| 清单阶段集合 == 磁盘阶段集合 | 把"登记与磁盘同步"变成独立判据 |

第 1 条是关键：没有它，"判据空转"与"状态干净"在观测上无法区分。

### ② 把元校验纳入门禁

`scripts/gate.py` 的 p0 阶段新增一步：

```
["-m", "pytest", "tests/contracts/test_contract_inventory_gates.py", "-q", "--no-header"]
```

它守的是**登记处作为唯一契约清单**这条性质：

- 存在但未登记的文件 ⇒ 必须被拒；
- 登记了但磁盘缺失 ⇒ 必须被拒；
- 登记了却没被任何阶段门禁覆盖 ⇒ 必须被拒。

**这三条此前从未在门禁里被跑过一次。**

### ③ 给新纳入的步骤配变异（2 条）

| 变异 | 结果 |
| --- | --- |
| `unregistered()` 不再报告「存在但未登记」 | **捕获** |
| `missing()` 不再报告「已登记但磁盘缺失」 | **捕获** |

两个判据**各自**被打到——只打一个等于只证明了半边。

## 五、已知限制

1. **`UNKNOWN_PHASES` 仍在导入时求值**——我只加了**事后检测**（跑完必须干净），
   没有改成惰性求值。这够用（泄漏会立刻被隔离守卫抓到），但更彻底的做法是把它改成 fixture。
2. **隔离守卫只覆盖 `CONTRACT_INVENTORY`**：其它模块级可变全局（若有）未纳入。
3. **门禁仍是「点名文件」模式**：新测试文件不会自动进网。本轮是手工加的第 25 步；
   没有"门禁必须覆盖全部测试文件"的判据——那本身是个可加的守卫。
