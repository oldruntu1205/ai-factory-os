# 运维面 · 健康与指标（上游 §14）

- 日期：2026-10-05
- 环境：**mock**（运行期存储是 JSONL journal；数据库迁移尚未接线到运行期）
- 判据：`scripts/gate.py --stages p2` **exit 0**；变异 `--phase p2` = **20/20 可捕获项全捕获**

## 1. 健康与就绪

| 端点 | 语义 | 实现 |
| --- | --- | --- |
| `GET /health/live` | 进程活着 | `app.liveness()` |
| `GET /health/ready` | 关键依赖 + 策略版本 + **积压** | `app.readiness()` |
| `GET /internal/v1/operations/metrics` | 指标快照 + 指标清单 | `metrics.compute_metrics()` |
| `GET /internal/v1/operations/metrics/text` | Prometheus 文本格式 | `metrics.render_prometheus()` |

### 本轮修掉的一处"永远健康"

`/health/live` 与 `/health/ready` 里的 `backlog` **此前硬编码为 0**。
这等于**永远报告无积压**——即使系统里堆满了未收敛的工作。
现在改为从 journal 真实派生：

```
未终结任务（tasks） + 未终结命令（commands）
  + 待决策批准（approvals） + inbox 未消费条目
```

对应变异「就绪积压重新硬编码为 0」被门禁捕获。

**这个派生本身也踩了一次坑**：第一版只统计命令/批准/inbox，
**漏掉了任务**——而任务写在**独立的 `tasks` journal** 里、不在 `commands` 里，
于是"受理了一堆任务"这种情况完全不计入积压。
实测现象：建一个 `ACCEPTED` 任务后 backlog 仍是 0。
是运行期用例（而不是单元用例）把它抓出来的——纯逻辑用例当时是绿的。

### 顺带修掉的"5xx 掩盖客户端错误"

排查 backlog 用例时用了 `/internal/v1/commands`（请求形状不对），
结果返回 **`503 INTERNAL_ERROR`** 而不是 4xx。

根因：该 handler 直接取 `body["command_type"]` 等字段，缺字段抛 `KeyError`，
被外层兜底成 503。**把调用方的错误报成"服务内部错误"**，
会让调用方以为服务坏了，也让排障的人去查错方向。

已加显式入参校验 → 现在返回 **400 `REQUEST_INVALID`** 并列出缺哪些字段。

**这次修复我也犯了一次过度收紧**：第一版把 `payload_version` / `payload_hash`
也算进必填——它们在编排链路里由上游产出、调用方本就不填，
于是把 P0/P1.5 的建命令用例打红了一片。
修正为只列**调用方必须自带**的 8 个字段。教训：
**"契约里是必填"≠"这个入口必须由调用方提供"**，加校验前要先确认调用方实际会带什么。

## 2. 指标（§14 点名项逐条对照）

| 上游要求 | 指标 | 事实来源 |
| --- | --- | --- |
| 任务成功率 | `task_success_total`（+ `success_ratio`） | `tasks` / `receipts` |
| 审批等待 | `approval_wait_seconds` | `approvals` |
| UNKNOWN 命令 | `unknown_command_total` | `commands` / `reconciliations` |
| 补偿失败 | `compensation_failure_total` | `sagas` / `compensations` |
| 投影延迟 | `projection_lag_seconds` | `inbox` / `outbox` |
| DLP 拒绝 | `dlp_rejection_total` | `egress-audit` |
| 模型耗时/成本 | `model_invocation_total`（受理计数）/ `governance_decision_seconds`（**治理判定**耗时）/ `model_cost_total` | `model-invocations` |
| Edge 漂移 | `edge_drift_total` | `edge-guard-decisions` |
| 拒绝率 | `edge_rejection_total` | `edge-guard-decisions` |
| 断连 | `edge_disconnection_total` | `edge-autonomy-decisions` |
| spool 容量 | `edge_spool_entries` | `edge-spool` |

### 一处**语义诚实**的改名（本轮）

指标原先叫 `model_invocation_seconds`「模型调用耗时」。但核查后发现：
**当前没有任何代码真正调用模型**——`/internal/v1/model-invocations` 只做准入治理判定。

记录任何数字都会造出"这是模型生成耗时"的假象，运维会据此按**错误的容量模型**做决策。
因此改成三项，各自名实相符：

| 指标 | 含义 | 记录什么 |
| --- | --- | --- |
| `model_invocation_total` | **受理次数** | 每次成功判定的调用计数 |
| `governance_decision_seconds` | **治理判定路径**耗时 | handler 内从进入到判定完成 |
| `model_cost_total` | 成本累计 | `null`（口径待冻结） |

指标描述与响应 `note` 里都写明「**不是**模型生成耗时」，并有专门用例守住这个命名
（`test_model_latency_metric_does_not_claim_to_be_generation_latency`）。

门禁断言：**§14 点名项与已登记指标必须一一对应**
（`signals_missing_upstream_requirement()` 必须为空；变异「指标清单漏掉一个上游要求项」被捕获）。

## 3. 为什么指标是"派生"而不是"累加"

两种实现方式：

1. 在每个业务动作旁边**累加计数器**；
2. 从已经 fsync 落盘的 journal **重新算**。

选 2。**计数器与事实是两份真相**——一旦某个分支忘了累加，指标就会长期偏离事实，
而且**没有任何东西会发现**。journal 是 append-only 的事实来源，
从它派生的指标天然与事实一致，并且可以随时复算核对。

## 4. 标签安全：为什么"封闭集合"是唯一可靠防线

上游 §14 明文：**指标标签不得包含客户名称、Prompt 正文或密钥**。

第一版实现只校验"值是否为令牌格式"（小写字母/数字/连字符/下划线）。
门禁用例立刻暴露了它的不足：**`sk-live-abcdef123456` 恰好符合该格式**——
一个疑似密钥被**放行**了。

因此改为**双重判定，且以封闭集合为主**：

| 层 | 判据 | 挡住什么 |
| --- | --- | --- |
| **取值范围封闭**（主） | 每个标签键必须声明**有限取值集合**，值必须落在其中 | 客户名称、Prompt 正文、任何自由文本、格式合法的密钥 |
| 格式受控 | 值还须匹配令牌格式 | 今后有人放宽集合时混入自由文本 |

**给不出有限取值集合的标签键，一律拒绝输出**——这等于承认该维度不该做标签。

### 两个配套设计

- **不做"清洗后放行"**：清洗会把非法输入静默变成另一个合法标签，污染指标口径。宁可拒绝。
- **未分类值必须有合法桶 `unknown`**：否则真实数据里的"尚未识别的取值"会把指标计算整个打挂。
  `unknown` 是受控桶，不是自由文本的落点。

### 一条被变异测试抓出的实现缺陷（值得记住）

第一版把"集合外的维度值"**静默过滤掉**。结果是：「去掉封闭取值检查」这个变异
**照样通过**——因为过滤条件本身也在用同一个集合，两边一起失效。

现在改为**显式失败**：集合外的维度值意味着代码产出了一个不该出现的维度，那是缺陷，
不该被悄悄掩盖。

## 5. 缺数据必须如实表达（不得用 0 冒充）

| 情形 | 表达 | 为什么 |
| --- | --- | --- |
| 无样本的成功率 | `success_ratio: null` | `0` 会被读成"成功率 0%"（系统全坏）；`null` 是"还没有样本" |
| 没有事实来源的指标 | 列入 `no_data` 数组 | 输出 `0` 会让人以为"健康" |
| 成本口径未定 | `total: null` + 明写"待冻结" | **不得编造占位数值** |
| Prometheus 文本 | `# <指标>: NO_DATA（原因）` | 抓取侧一眼可辨 |

对应变异「无样本的成功率返回 0」「成本指标编造占位数值」均被捕获。

## 7. 已知限制

1. **环境是 mock**：运行期存储是 JSONL journal，数据库迁移尚未接到运行期。
2. **无指标抓取端点鉴权**：`/internal/v1/operations/metrics` 目前与 `/health/*` 一样
   不要求 Context。生产需按内部网络 ACL 限制（上游要求内外接口不同认证受众）。
3. **耗时/延迟类样本为 0**：需要适配器回报 start/end；当前只有计数。
4. **成本口径待冻结**：真实模型报价与计入方式未定。
5. **未接真实监控系统**：Prometheus 文本只是渲染格式，没有实际抓取验证。
6. **积压口径**是"未终结命令 + 待决策批准 + inbox 条目"，
   生产口径是否要纳入 spool / outbox 待与运维冻结。
