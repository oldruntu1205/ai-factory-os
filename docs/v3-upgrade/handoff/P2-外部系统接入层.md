职责**只有一件**：把外部系统的原生记录，确定性地翻译成 V3 事件事实。
事件的排序、去重、迟到处理已在 `services/_kernel/events.py` 实现，这里不重复。

## 2. 三条硬规则（都来自上游，都能被门禁证伪）

### 2.1 不编造生产值（§16.1 明文）

> 对未填项实现显式配置和 Mock，**不填编造的生产值**。

| 情形 | 处理 |
| --- | --- |
| 缺必填字段 | **拒绝**，报错**点名**缺哪些（多个一次列全） |
| 非必填字段缺失 | 进 `unmapped` 清单，**不补值** |
| 单位不在登记表 | **拒绝**，不做"取近似" |
| 工厂本地时间无时区 | **拒绝**，不假设是 UTC |

### 2.2 `aggregate_version` 必须来自权威系统

上游要求「重复/乱序/中断恢复不破坏事实；权威版本清楚」。
版本由外部系统给出，适配层**绝不代为推断或累加**——
猜出来的版本会让乱序事件静默覆盖新事实。

配套：`event_id` 从**外部权威标识 + 版本**派生，于是同一条记录重放得到同一个 id，
被 inbox 去重规则收敛，而不是每次造一条新事实。

### 2.3 时区必须显式

契约 `UtcTimestamp` 要求 `Z` 结尾、**禁止本地时区**。而外部系统常给本地时间。

这类值**没有**可推导的 UTC 含义：工厂时区一旦猜错，事件整体平移几小时，
**而所有校验依然通过**——属于最危险的一类错误（不报错、查不出）。

所以只有两种合法输入：

| 输入 | 处理 |
| --- | --- |
| 已带显式偏移/`Z` | 归一为 UTC |
| 无时区的工厂本地时间 | **必须**提供 `factory_timezone`，按其换算 |
| 两者都不是 | **拒绝** |

门禁里有一条专门证明"时区真的参与了换算"：同一本地时间在 `Asia/Shanghai`
与 `UTC` 下必须得到**不同**的 UTC 结果。

## 3. 单位与温度：倍率表 + 独立的偏移处理

倍率表只放**纯倍率**换算（cm→mm、kg→g、min→s）。
**温度单独处理**（华氏→摄氏含偏移），并且倍率表里显式留 `("fahrenheit","c") = None`，
使"误走倍率表"必然报 `UNSUPPORTED_CONVERSION` 而不是算出一个错值。

实测：`12.5 cm → 125 mm`、`194 °F → 90 °C`、`250.5 kg → 250500 g`。

## 4. 接入侧还要守一条领域语义（§17 A11 的落点）

MES 报工：**合格 + 报废 = 报工总数**。不自洽即拒绝，**不取其一**。

> 数量不自洽意味着现场数据本身有矛盾（漏报、重报或人工改数）。
> 静默取一个值会让账实差异一路流到库存与成本，而且**再也查不出来**。

缺"报工总数"同样拒绝——没有总数就无法核验自洽，不能跳过校验直接接受。

## 5. 本轮抓到的两个自己写的缺陷

### ① 测试目录名遮蔽了被 import 的包

套件原名 `tests/integrations/`。pytest 的 rootdir 是 `tests/`
（仓库里没有 pytest 配置文件），于是 `tests/integrations/` 先被找到，
`import integrations` 解析到**测试目录自己**，`integrations._base` 自然不存在。

> **通用规则：测试目录名不要与仓库根的被测包同名。**

已改名 `tests/p2_integrations/`，并把这条写进套件文档字符串。

### ② `payload_hash` 在单位换算之前定稿

WMS/PMC 适配器在 `normalize_event` 返回**之后**才做 kg→g、min→s 换算，
而哈希在那之前就算好了 ⇒ **哈希描述的不是最终内容**。

对账时无法自证，而且不会有任何报错。已抽出 `seal_payload()`，
在所有变换之后统一封哈希；并有一条用例（`test_result_payload_hash_matches_recomputation`）
对四个适配器逐一复算比对。

## 6. 需要外部提供什么（对接清单）

每个适配器的 `mock.py` 里都有 `REQUIRED_FROM_<SYS>` 清单，门禁断言其**非空**
且**必须涉及"时区"**。四份清单共同的缺口：

| 类别 | 需提供或冻结 |
| --- | --- |
| 产品与版本 | 各系统产品名与版本号（决定 API 形态） |
| API 授权 | 调用凭据与授权范围（**凭据只走密钥管理，不入仓**） |
| 对象 ID 与字段 | 单据/工单/事务号等编码的字段名与取值口径 |
| **单位** | 各数量字段的原始计量单位（未登记换算一律拒绝） |
| **时间与时区** | 时间字段是本地时间还是带偏移；**工厂时区标识** |
| 拉取方式 | webhook 还是轮询；频率与限流上限 |
| 版本语义 | `version` 是否严格单调、何时递增 |

## 7. 已知限制（不做假的确定性）

1. **全部为 Mock**：`status="mock"` 写在映射声明里，并随事件一起可见；
   归一化时会**校验**该字段取值，声明被改成非法值即拒绝。
2. **没有真实系统联调**：无网络调用、无鉴权、无限流——这些都依赖 §16.1 的外部输入。
3. **字段名是自拟的**：`header.doc_no` 等路径是**我方对 ERP 的期望形状**，
   不是真实 ERP 的字段。真实字段到来后需替换映射声明（代码结构不变）。
4. **单位表只登记了 3 类量**（长度/质量/时间）与温度；其余量纲未登记即拒绝。
5. **四类事件各只实现了 1 个事件类型**（`erp.demand.released` 等）——
   上游 §16 的"主数据同步、计划/进度/库存投影、对账"尚未接入。
