- 判据：`scripts/gate.py --stages p0,p1,p15,p2,p3,p4,assertions` **exit 0**（1270 用例）；

## 一、为什么这两件东西值得单独做

前 22 轮做了大量取舍，它们此前只散落在**代码注释**与**交接文档**里。

后果很实际：后来的改动者看不到"为什么当初这么选"，
于是很容易用一个看似合理的改动，把上游明确要求的性质破坏掉——
**而门禁未必抓得住语义层面的那种破坏**。

运行手册同理：本项目踩过的坑（并发抢端口导致假失败、判定函数读墙钟导致
永久失败）都**又踩过第二次**。写下来才算真的学会。

### 0006 值得单独说：它不是"没做完"，是"有意不做"

上游 §15 列了 `edge/{agent,inference,guard,adapters}/` 四个目录，
同时明文说明 Edge 节点**不计入**那 8 个核心应用单元。

Edge 的**语义**是 P4 的核心（Guard 阶段与优先级、影子不产生动作、
互锁不可被置信度覆盖、spool 只补报事实、断连自治需有效发布）——
这些**已经在门禁里**，有真实多进程断言。

而"把代码放进 `edge/` 目录"是**部署形态**问题。
`ls edge/` 会显示不存在——**这是有意为之，ADR-0006 就是它的书面依据**。

> 先建四个空目录会产出**没有验证内容的骨架**，
> 给人"已完成"的错觉，比缺失更糟。

## 三、runbooks：5 篇，都对应真实执行过的动作

| 手册 | 什么时候看 |
| --- | --- |
| 01 本地起后台并查看 | 要在浏览器里看管理后台 |
| 02 门禁红了怎么定位 | 门禁报红（**现象→原因→处理**） |
| 03 新增接口的完整流程 | 加一条路由/字段 |
| 04 变异测试与"守卫自证" | 确认某个守卫"真的有牙" |
| 05 集群与端口规则 | 服务起不来 / 端口冲突 / 假失败 |

**三条贯穿铁律**（写在索引最显眼处）：

1. **门禁必须串行跑**——本项目因此误判过**两次**，一次还被归因成代码缺陷；
2. **判定函数不得读墙钟**——否则结论不可复现，夹具迟早跨过常量时刻而永久失败；
3. **修完缺陷要补"改回去会被抓住"的变异**——否则修复会被无声撤销。

## 四、门禁：把"文档该写的东西写没写"变成机械判据

`tests/infra/test_adr_records.py`（78 条，随 `tests/infra` 一起在门禁里）：

**ADR 部分**

| 断言 | 为什么 |
| --- | --- |
| 文件名 `NNNN-<kebab>.md` | 编号是 ADR 互相引用的凭据 |
| 必备章节（背景/决策/后果/备选方案） | 缺"备选方案"就只是宣布，不是决策 |
| **状态在封闭枚举内** | 状态是 ADR 唯一可机读的结论；允许自由文本等于让"已接受"失去约束力 |
| 写了上游依据/外部约束 | 没有依据的决策无法被检验，也无法判断何时该推翻 |
| **索引列出每一篇** | 不登记索引的 ADR 等于不存在 |
| **索引状态与正文一致** | 两处状态必然分叉，看的人无从判断该信哪个 |

**runbook 部分**

| 断言 | 为什么 |
| --- | --- |
| 文件名 `NN-<名称>.md` | 故障时能按顺序找 |
| 有可执行命令块 | 没有命令的手册只是文章 |
| **排障类**手册必须有「现象→原因→处理」 | 故障时最需要的正是这一节 |
| 用了仓库 venv 就必须交代工作目录 | "在错误目录下执行"是手册最常见的失效方式 |
| 索引列出每一篇 + 写明三条铁律 | 最容易看到的地方必须出现最常踩的坑 |

### 门禁在写的过程中抓到了我三次

1. **状态行混了说明文字**（`已接受（临时）** · 待外部依赖解锁后由 ADR 取代`）
   ⇒ 状态不再可机读。修法是把"取代条件"另起一行，**不改判据**。
2. **runbook 02 用了"常见红法"** 而不是"现象" ⇒ 判据要求"现象"字样，
   **是我该改**（"红法"确实不如"现象"直白）。
3. **runbook 03/04 没写工作目录** ⇒ 补 `cd`。

> 三次都是"文档确实该改"，没有一次需要放宽判据——
> 这说明判据定得对。

## 五、判据的边界（诚实说明）

门禁守的是**结构**：编号、章节、状态枚举、索引完整性、可执行性。

**它不守内容对不对。** 一篇格式完美但结论错误的 ADR 照样通过。

这一点必须写明，否则会给人"ADR 已被机器验证"的错觉。
门禁只能回答"该写的东西写没写"，**内容仍需评审**。

## 六、已知限制

1. **ADR 只覆盖 6 项**：本项目还有若干取舍（如"测试目录不得与仓库根包同名"、
   "变异后必须语法合法"）没成文——它们目前写在代码注释里。
   补齐应当按"改动者最可能看不到"的优先级来做，而不是凑数。
2. **runbooks 偏开发/本地**：生产处置（告警响应、备份恢复、发布回滚）
   **尚未编写**，因为生产形态本身未冻结（见部署清单的 `blocked_by`）。
3. **没有"文档新鲜度"检查**：ADR 可能与代码漂移（例如某个被引用的函数改名）。
   目前只能靠人读。
4. 两份目录都在 `docs/` 下、不在门禁的 `--stages` 命名空间里；
   它们随 `tests/infra` 一起跑（步骤名"基础设施清单"）。
