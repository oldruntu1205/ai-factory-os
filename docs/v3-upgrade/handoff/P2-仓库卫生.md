# 仓库卫生 · 测试产物不得污染仓库

- 日期：2026-10-05
- 判据：`scripts/gate.py --stages p2` **exit 0**；变异 `--phase p2` = **25/25 可捕获项全捕获**

## 1. 现象：仓库根躺着 45 个测试数据库

盘点时发现仓库根有 **45 个 `test_mcp_*.db`，合计 20.95MB**，而 `.gitignore` 里
`*.db` 早就被明确忽略——也就是说它们从来不该出现在那里。

追下去发现这不是"偶发漏清"，而是**结构性的**：

```python
# backend/tests/test_hermes_mcp_scheduler_audit.py（修复前）
os.environ["SQLITE_PATH"] = f"./test_mcp_{os.getpid()}.db"
```

问题有两层：

| 层 | 问题 |
| --- | --- |
| **路径** | `./` 是**进程工作目录**。从仓库根跑 pytest，每个用例进程都在仓库根拉一个库 |
| **清理** | 清理写在 `main()` 末尾，而 pytest 导入模块时**不执行 `main()`**（被 `__main__` 守卫挡住）⇒ 永远不清理 |

同类写法在 `backend/tests/` 下共 **5 处**（`test_api` / `test_channels` /
`test_hermes` / `test_marketplace` / `test_hermes_mcp_scheduler_audit`）。

## 2. 修法：共享一个 helper，而不是各改各的

新增 `backend/tests/_test_sqlite.py`，`isolate_sqlite(prefix)` 做三件事：

1. **路径指向系统临时目录**（`tempfile.gettempdir()`），与仓库根彻底解耦；
2. **`atexit` 注册清理**——正常结束、断言失败、异常退出都会跑；
3. **启动时清扫**上次被硬终止留下的同前缀过期文件。

第 3 条是必要的：`atexit` 在进程被强杀（超时、任务管理器）时不会执行；
更常见的是 Windows 上 SQLite 句柄未释放导致 `unlink` 失败。
所以泄漏是**有界的**（下次运行清掉过期残留），不是无界的。

实测：从仓库根跑该脚本，**仓库根新增 0 个文件**，64 项测试全通过。

## 3. 加守卫，并**验证守卫自己有效**

新增 `tests/p2_runtime/test_repo_hygiene.py`：

- 仓库根不得新增 `test_*.db`（既有 45 个按前缀登记为基线，**只减不增**）；
- 任何 Python 文件不得把持久化路径设成**相对路径**或**指向仓库内**。

### 这一节是本节最值得记的部分：守卫的三次自伤与一次假绿

**第一次：守卫匹配到自己**。守卫的文档字符串里引用了旧的错误写法，
于是它把自己报成违规。

**第二次：为躲开自伤而"抹掉字符串"，结果抹掉了要检测的东西**。
`./x.db` 就在字符串里——抹掉字符串就再也检测不到相对路径。

**第三次：`" ".join(tokens)` 把空格插进了字符串内部**。
`f"./x.db"` 被拼成 `f" ./x.db"`，正则里的 `f"` 后面多了个空格，永不命中。

**而真正危险的是第四次——"假绿"**：

变异测试显示，「把相对路径检查改成 `if False`」这个变异**门禁照样全绿**。
原因是当时仓库里**没有任何相对路径写法**，
于是"守卫探测能力为零"与"恰好没东西可探测"在观测上**完全无法区分**。

> **一个探测能力为零的守卫，比没有守卫更危险**——它给人一种"有人在看着"的错觉。

修法：把判据抽成**唯一一份**（`_scan_relative_persistence`），
主守卫与自检**共用它**，再喂**构造样本**断言守卫必须报出来：

| 自检用例 | 断言 |
| --- | --- |
| 能力自检 | 构造 1 条合法 + 2 条违规 ⇒ **正好**报 2 条（多报合法项即失败） |
| 反向自检 | 绝对临时路径 ⇒ 报 0 条（否则会逼人加豁免、最终失去守卫） |
| 误报自检 | 文档字符串里的反面示例 ⇒ 报 0 条 |

**样本里必须混入一条合法项**：第一版样本三条全是违规项，
于是"完全不判断"照样返回 3 条、照样通过——自检形同虚设。

抽成唯一一份判据也是必需的：原先主守卫与自检各有一行**完全相同**的正则，
变异只改到其中一份，另一份继续工作，于是自检从根上失去意义。

## 4. 明确记录的局限（不做假的确定性）

**门禁结构上看不到原始症状**：`backend/tests/*.py` 是**独立脚本**，
不在 `scripts/gate.py` 的运行范围内（门禁只跑 `tests/` 下的套件）。
所以"它往仓库根写库"这件事，门禁**观察不到**——
这也正是最初能攒下 45 个文件的原因。

已按 `[已接受]` 如实登记这类缺口（而不是删掉变异假装全捕获）。
**根治需要把 legacy 套件纳入门禁**，属单独一步。
