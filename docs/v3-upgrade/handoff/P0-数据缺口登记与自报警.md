# 数据缺口登记：把"缺数据所以做不了"变成**会自己报警**的断言

- 日期：2026-10-05
- 依据：上游 §15（`apps/web-admin` 应有员工/发布/对账页）、§17 A06
- 判据：`scripts/gate.py --stages p0,p1,p15,p2,p3,p4,assertions` **exit 0**（1365 用例）；
  变异 **156 个可捕获项全捕获**

---

## 一、我一直在写一句**不准确**的已知限制

连续几轮，我在"已知限制"里都写着：

> 员工页未做——`employees` 没有对应路由。

**这句话不准确，而且它会掩盖真问题。** 本轮核实后确认：

| 层 | 状态 |
| --- | --- |
| 路由 | 缺（**可以加**） |
| **员工数据模型** | **根本不存在** |

`registry.mock.json` 里每个租户只有：

```json
"employees": ["employee-planning"]
```

—— **裸 ID**。全仓搜 `employee_actor` / `actor_ref` / `assignments`：**0 次**
（`roles` 那几处是**知识文档的可见角色** `pmc.read`，不是员工角色）。

**所以"加个路由就能出员工页"是错的：加了也只能显示一个裸 ID，那是装样子。**

我**没有**加那个页面。这一轮做的是把缺口变成**会自己报警的断言**。

## 二、为什么"记一笔已知限制"不够

> **已知限制不会自己报警。**

它会在数据到位后**静静地过期**，而没人知道那一页该做了。
所以本轮把每个缺口登记成**当前为真、数据一到就变假**的断言——
于是**数据到达时门禁报红**，强制下一步动作。

## 三、登记了什么（5 项缺口）

| 缺口 | 缺什么 | 阻塞什么 |
| --- | --- | --- |
| `employee_actor_binding` | **员工 ↔ 执行身份（actor）的绑定** | 员工页（§15）——没有绑定就只能显示一个裸 ID，无法回答"这个 AI 员工是谁、能做什么" |
| `position_authority_matrix` | **岗位与授权矩阵** | 批准的 `position_authorized` 检查——只能 `UNKNOWN` |
| `risk_grade_limits` | **按风险等级的授权限额** | 批准的 `within_limit` 检查——只能 `UNKNOWN`；限额是"能不能批"的**硬前提** |
| `config_authority_roster` | **谁能改配置的名单** | §10.1 职责分离——`checkAuthoritySeparation` **生产 0 消费** |
| `real_posting_evidence` | **真实过账凭证** | `posting_status` 恒 `NOT_CONFIRMED`——界面**永远不会**显示「已过账」 |

每项都写了"**数据到位后必须做什么**"，这样触发时下一步是明确的。

## 四、门禁（7 条）

`tests/infra/test_data_gap_register.py`：

| 用例 | 断言 |
| --- | --- |
| 员工↔actor 绑定仍不存在 | 一旦出现该字段 ⇒ **报红**，强制补员工页 |
| `employees` 目前只是裸 ID | 判据取**数据形状**（若变成对象列表 ⇒ 报红），比字符串搜索稳 |
| 授权限额仍不存在 | 出现 `limit`/`quota`/`max_amount` ⇒ 报红 |
| 配置权名单仍不存在 | 出现 ⇒ 报红，并指向两处需要同步更新的登记 |
| **缺口确实阻塞下游** | `CHECK_REQUIREMENTS` 必须逐项点名三个缺数据检查各自要什么 |
| 无过账凭证时界面不得显示已过账 | §6 不变量的界面侧 |
| **能力自证** | 喂构造数据，检测手法必须**报出"有"** |

**能力自证那条是关键**：没有它，
"字段名写错导致永远检测不到"与"数据确实还没来"**在观测上无法区分**——
缺口守卫会变成永不触发的装饰。

## 五、变异

| 变异 | 结果 |
| --- | --- |
| 员工数据缺口登记失真（把裸 ID 改成结构化记录） | **捕获** |

这个变异的锚点要注意：`"employees": ["employee-planning"],` 在文件里出现 **2 次**
（两个租户），而 `apply_mutation` 要求原文**唯一**——
所以锚点带上了后面两行（`delegated_scopes` + `max_data_class: C2`）才唯一。

另外专门校验了**变异后 JSON 仍可解析**（改的是数据文件，语法合法不等于结构可用）。

## 六、已知限制

1. **员工页仍未做**——而且**现在有明确的开工条件**：需要先有员工数据模型
   （员工↔actor 绑定、岗位、限额），而不是先加路由。
2. **登记是人工维护的**：新出现的缺口需要有人登记；守卫只保证"已登记的不静默消失"。
3. **字段搜索是启发式的**：`limit` 之类的子串可能误命中（例如注释里出现该词），
   届时会报红并要求人核对——这是**可接受的失败方向**（吵醒人，而不是漏掉）。
4. **`test_the_gap_detectors_can_actually_detect` 用的是内存构造数据**，
   不是真实登记表；它证明的是判据逻辑可用，不是"数据一定会被这样写"。
