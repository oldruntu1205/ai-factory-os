## 第一部分：批准页判定（`apps/web-admin/src/approval.js`）

### 1. 态度：能验的验，缺数据的**说缺**

先核查了登记表，结果很关键：`registry.mock.json` 里只有
`tenants.*.actors` 与 `delegated_scopes`，**没有角色、没有岗位、没有限额**。

而上游 §16.1 把"身份和批准岗位（SSO、tenant/factory 边界、角色、职责分离、限额）"
明列为**外部依赖**。所以本轮**没有实现一个假的限额检查**——
拿不到阈值就编一个，等于给人"已经管控了"的错觉。

做法是分三类判定：

| 检查 | 数据来源 | 结论 |
| --- | --- | --- |
| 批准是否有 binding | 记录本身 | PASS / **FAIL** |
| 审批人 ≠ 发起人 | 记录本身 | PASS / FAIL / UNKNOWN |
| 是否已决定（不可改判） | 记录本身 | PASS / **FAIL** |
| 有效期 | 记录 + **调用方传入的 now** | PASS / FAIL / UNKNOWN |
| **管理权与批准权分开** | **无数据** | **UNKNOWN** |
| **是否在限额内** | **无数据** | **UNKNOWN** |
| **是否属于授权岗位** | **无数据** | **UNKNOWN** |

汇总规则：**明确阻塞压倒未知**。有 FAIL ⇒ `BLOCKED`；无 FAIL 但有 UNKNOWN ⇒ `UNKNOWN`；两者都没有才 `DECIDABLE`。

门禁里有一条**诚实性断言**：

> **在当前数据条件下，没有任何输入能得出 `DECIDABLE`。**

一旦角色与限额数据接入，这条用例应当被**显式改掉**，而不是悄悄失效。

### 2. 自然语言不得冒充授权（上游明文）

这条最容易在 **UI 层**失守：一个"意见"输入框 + 一个"通过"按钮，
很容易做成"填了意见就算批准了"。

所以 `normalizeDecision()` 直接拒绝：

- `approved` 必须是**真布尔**——`"true"`、`1`、`"yes"` 都不算；
- **说明文字里出现「批准/同意/通过/ok/approved/yes/go ahead」⇒ 拒绝**，
  理由写明"授权只来自 approved=true/false 这个结构化字段"。

> 不是为了禁言，而是防止"填了说明就算批准"这种界面误导。

### 3. 结论必须可复现

`assessApproval` 要求调用方传 `decidedAt`。**不给就不判过期**（记为 UNKNOWN）。

理由：用本机时钟会让同一份记录在两次评估中得出不同结论，
而批准的有效性结论是要被审计的。门禁断言"同一输入重复评估结果完全相同"。

## 第二部分：修掉一个**永久失败**的时间脆弱性缺陷

### 1. 症状与误判

跑门禁时 `tests/p3_transactions::test_kernel_and_review_view_agree_and_accept_both_approval_shapes`
报 `reason-lease-expired`。

第一反应是"我和后台任务并跑导致端口冲突"。**这个判断是错的**——
先跑单条就复现了，且它与端口无关。

### 2. 根因

```python
# transactions.py（修复前）
def _lease_unexpired_static(expires_at):
    return expiry > time.time()      # ← 读墙钟
```

而 `review_command` 里**早就算好了**：

```python
moment = _epoch(now or utc_now())    # ← 契约要求的判定时刻
```

**租约判定根本没用这个 `moment`。** 于是：

- 测试夹具用固定常量 `UTC = "2026-10-05T00:00:00Z"` 当租约到期时间；
- 墙钟一走过该时刻（就是今天），这条用例**永久失败**，且与代码对不对无关；
- 表象像是"跑得快/慢"或"并跑冲突"，**误导排查方向**。

### 3. 修复

```python
def _lease_unexpired_static(expires_at, *, moment=None):
    ...
    return expiry > (moment if moment is not None else time.time())
```

调用点传 `moment=moment`。

**为什么不是改测试**：夹具传了 `now` 是**对的**——
`review_command` 的整个设计就是"判定只用传入的 now"（结论要可审计、可复现）。
真正失效的是实现里那一处漏掉的传参。改测试等于把设计意图废掉。

`routes.py` 里另有一个同名的 `_lease_unexpired` 也做了同样处理（加了 `moment` 参数），
但它的三处调用都在 HTTP handler 内——**那里读墙钟是正确的**（请求时刻就是现在），
**没有改动调用点**。

### 4. 验证（两侧极端时刻）

```
expires_at = 2026-10-05T00:00:00Z
  传 moment=2023 年  -> True
  传 moment=2100 年  -> False
```

只要实现读墙钟，两次必得同一结果——所以这条判据能真正分辨。

### 5. 回归断言与变异

新增 `test_lease_expiry_follows_the_injected_now_not_the_wall_clock`（标 A06），
并配一条变异「租约过期判定改回读墙钟」——**门禁正确报红**。

> 缺陷修完不算完：**必须让"改回去"这件事被门禁抓住**，否则它下次还会被改回来。

## 第三部分：本轮用到的通用方法（值得复用）

1. **时间敏感判定必须接受注入的时刻**。判定函数读墙钟 ⇒ 结论不可复现、
   夹具迟早跨越常量时刻、且失败表现会误导排查。
2. **"跑快了"不一定是并发问题**。先单跑复现、再看是不是墙钟跨点。
3. **修完补回归断言 + 变异**，否则修复会在下次重构中被无声撤销。
4. **修 bug 要挑对位置**：这处该改实现（设计意图明确），不该改测试。
