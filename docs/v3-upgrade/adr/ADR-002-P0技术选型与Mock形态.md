# ADR-002：P0 技术选型与 Mock 形态

- 状态：**已采纳**（2026-10-04）
- 上游依据：§13（数据存储与所有权，属"建议基线"）、§14.2（首期部署基线）、
  §15（"消息产品、向量后端、实际依赖版本在 L2 的 P0 ADR 冻结"）、§16（P0 完成条件）
- 影响范围：P0 骨架实现、P1–P3 的选型前提

## 背景

上游把若干选型标为**建议基线**（可经 ADR 调整）：PostgreSQL / Redis / 本地对象存储 /
受 ACL 的向量后端 / 持久化消息代理；并明确"具体消息产品、向量后端和版本在 P0 选型 ADR 冻结"。
另有若干项是**必须**（每 owner 独立 schema/role/迁移、RLS 作第二道隔离、禁止跨 owner 写表）。

## 决策

### 1. P0 骨架的语言与运行时

- **语言**：Python 3.13（与既有 `backend/` 同一解释器与 venv，避免第二套工具链）。
- **HTTP**：标准库 `http.server`。P0 只需 15 条契约接口 + 健康基线，
  引入 FastAPI 会让"契约形状"被框架的 schema 生成覆盖，反而弱化"契约是唯一来源"。
  **P1 重新评估**：若需要 OpenAPI 自动生成、依赖注入与中间件生态，切到 FastAPI/uvicorn，
  契约包不变（客户端由 OpenAPI 生成，不手写数据结构）。
- **测试**：pytest（仓库原先不装 pytest，已拆出 `packages/contracts/requirements-dev.txt`
  单独管理，不污染 `backend/requirements.txt` 的在产运行依赖）。

### 2. 数据存储（P0 → P1+）

| 项 | P0（本阶段） | 目标态 | 状态 |
| --- | --- | --- | --- |
| 业务状态 | 内存 dict + JSONL journal（仅 Mock 闭环用） | PostgreSQL，每 owner 独立 schema/role | **待 P1/P2 落地** |
| 迁移 | 各 owner 迁移目录只有说明，无 DDL | 每 owner 独立迁移目录，不改已应用迁移 | 目录已就位 |
| 缓存/限流 | 无 | Redis | 待 P2 |
| 事件 | 无 broker；跨进程用追加式 JSONL 模拟 | 持久化消息代理 + outbox/inbox | 待 P2 |
| 向量 | 无 | 受 ACL 的向量后端（V2.1 已用 Qdrant，作为候选） | 待 P2 |
| 对象存储 | 无 | 本地对象存储（证据/原始内容） | 待 P2 |

**为什么 P0 就引入 journal 而不是纯内存**：P0 完成条件之一"Mock 闭环可追踪"要求
**回执驱动命令状态**——命令成功必须由权威回执决定，不能由调用链上的服务自己宣布。
纯内存无法跨进程表达这件事，会逼出"命令服务自己写 SUCCEEDED"这种违反上游 §12 的实现。
journal 是**最小可验证形态**，不是生产方案。

### 3. Mock 与真实依赖的边界

- 未冻结项一律实现为**显式配置 + Mock**，不填编造的生产值。
- 登记表（tenant / tool / model backend / policy / 部署映射）在 P0 是
  `services/_kernel/registry.mock.json`；**缺失或不可读时启动即失败**（fail-closed），
  不存在"默认放行"分支。
- 端口：登记表给基线端口；本地验证可用 `V3_PORT_<SERVICE>` 覆盖
  （本机存在 Windows 保留端口，bind 会返回 WinError 10013）。
  **这是本地验证专用机制，不是生产配置项。**

### 4. 认证（P0 占位）

- 契约要求：外部 / 内部 / 现场使用**不同认证受众与网络 ACL**。
- P0 只校验"存在 Bearer + 服务身份登记"，**不校验真实签发与受众**。
- **待冻结**：SSO 方案、受众值、密钥投放方式（阻塞 P1 的用户面与 P3 的写入）。

## 需要跟随的硬约束（不可 ADR 调整）

1. 每 owner 独立 schema + 独立 DB role + 独立迁移目录；
2. 禁止跨 owner 写表 / join / 外键；
3. 所有业务主键、唯一索引、幂等域必须包含 `tenant`；
4. RLS 作第二道隔离，应用层身份检查仍为必须；
5. C3/C4 只在批准的本地域处理，本地故障不得自动降级公网。

## 重新评估时点

- **P1 启动时**：是否切 FastAPI、认证方案定稿；
- **P2 启动前**：消息产品 / 向量后端 / 对象存储定稿（需外部依赖方参与）；
- **P3 之前**：Command 存储与 Saga 落库形态定稿。
