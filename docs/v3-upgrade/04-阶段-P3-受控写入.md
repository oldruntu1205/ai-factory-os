202 仅为持久化受理；200 仅为可信事实/查询返回，均不证明业务成功。相同命令的执行请求重复返回原 command 与状态 URL；读取 execution-record 获取当前结果。P0 既有写入口也必须统一执行 P3 强制管道，不能保留绕过口。

统一 Error 复用 P0：400/422 结构参数；401/403 身份权限；409 幂等/版本冲突；429 预算；503 依赖不可用。不新增生产业务 code；具体 code、reason 目录待冻结。HTTP 超时或 5xx 不能证明外部未执行，调用方查既有 command，不能创建新键。

## 3. 批准事实、绑定字段与 TOCTOU 复核点

Fact 保存 approver_ref、decided_at、approved、decision_ref、record_version、audit_intent_ref、有效期与 Binding。批准人来自可信身份；binding.context.actor_id 是受委托执行人，两者分别核对。管理权不替代业务批准权；职责分离由 Business Control 校验，真实岗位/限额待冻结。

| 绑定字段 | 可信来源 / 要求 | 变更处理 |
| --- | --- | --- |
| context.tenant_id / factory_id / actor_id / task_id | 身份、工厂、委托、任务关联 | 越域拒绝，不复用不同主体/任务的批准 |
| object_id / expected_version | Harness 与权威对象/版本 | 版本变化阻止执行，核实方案并重新批准 |

| payload_schema / normalization_ref | Schema 版本/hash、可信规范化事实 | 不匹配拒绝 |
| tool_id / tool_version / command_type | ToolSpec 与登记动作目录 | 工具/动作变更重新准入及批准 |

| policy_version / policy_evaluation_ref | control-plane 权威当前策略 | 旧版本重新评估 |
| valid_from / valid_until / decided_at | 可信 UTC Z 时间 | 生效前/过期后禁止执行 |
| approver_ref / record_version / decision_ref | 独立事实、服务端 CAS | 并发仅一个有效决策；同决策重放原事实，异决策/绑定 409 |
| permission_evidence_ref / checked_at | 执行时当前权限证据 | 批准后撤权同样阻止执行 |

可信 Tool 规范化/hash，Transaction 落库复算并核验引用内容与绑定；Agent 提供的值不作权威。幂等 fingerprint 包含 canonical payload 及对象/工具/版本/动作/委托等不可变绑定。同 tenant+key 同绑定返回同 command/当前结果，异 payload 或绑定 409。恢复仍引用同一原命令，不能重新解释原命令内容。

| 复核点 | 必须校验 | 失败观察 |
| --- | --- | --- |
| 批准决定写入 | 当前批准权限、职责分离、绑定、对象/策略、有效期、批准记录 CAS，持久化审计意图 | 拒绝；有效批准不能被并发覆盖 |
| AUTHORIZED → EXECUTING 前 | 当前批准、hash、策略、动作、对象版本、当前权限/委托、租约、fencing、对象锁、未开始取消意图 | allowed=false、受控 reason_ref；不派发 |

Review allowed=true 要求所有检查位 true。approval_ref=null 仅用于权威策略证明无需审批，不能自行放行；有效期取批准/策略许可/租约/任务 deadline 的有效交集。跨字段相等、时间大小、引用内容真实性由 L2 强制，JSON Schema 不伪装可证明。Review/批准不可作为永久缓存许可。

## 4. Command、执行凭证与 fencing

Command 原样复用 §12：ACCEPTED → AUTHORIZED → EXECUTING → SUCCEEDED/FAILED/UNKNOWN；可进入 MANUAL_REVIEW。不新增 Command CANCELLED 或超时失败状态。Task/Run 是编排投影，受理/授权/UNKNOWN 不能标业务成功或已过账。

Credential 保存 command_id、原幂等键、Binding、pre_state_ref/hash、review_ref、lease、execution_permit_ref、audit_intent_ref、started_at、record_version。先持久化命令、前置状态、执行意图、审计意图，再派发。Command/步骤账/派生 outbox 在 owner 本地事务提交；可信回执、Command 状态、outbox 同本地事务，跨 owner 不共享数据库事务。

Lease 保存 worker_ref、issued_at/expires_at、lease_ref、record_version、fencing_token、object_lock_ref。token 由 Transaction 服务端分配，tenant+factory+object 范围持久单调递增；接管增加 generation，旧 worker 续租/派发/状态及步骤提交拒绝。对象锁同范围串行；TTL 到期不是前次未执行证据，不能盲派发。

源系统不支持远程 fencing 时，由 adapter 台账、串行入口与人工对账覆盖在途动作，不宣称 token 能撤销已发出的外部调用。晚到真实凭证由已认证 adapter receipt 入口独立核实，不能因拒绝旧 worker 丢弃权威事实。

Checkpoint 恢复先查既有 command，再继续；成功步骤不重跑。EXECUTING 无明确回执按 UNKNOWN 查询；租约失效不是 NOT_EXECUTED。

## 5. UNKNOWN 收敛决策表

Record 保存 command/原键/hash、源系统、查询次数、证据引用/hash、source_outcome、候选/禁止动作、next_action、retry_idempotency_key、recorded_receipt、人工队列、错误及时间。source_outcome 复用 P1.5 outcome；动作值是决策标签，均非新生命周期状态。

| 证据 | 必须下一步 / 候选动作 | 命令观察 | 禁止项 / 人工条件 |
| --- | --- | --- | --- |
| 超时/无回执，尚未查询 | QUERY_SOURCE；候选仅 [QUERY_SOURCE] | UNKNOWN，business_success=false、NOT_CONFIRMED | RESEND_NEW_KEY（换新幂等键重发）、DIRECT_COMPENSATION（直接补偿） |
| 查源确认成功且独立核实绑定 | 持久化回执；候选 []、next_action=null | SUCCEEDED，posting 按独立过账证据 | 禁止再次执行；accepted 不能当成功 |
| 可信 NOT_EXECUTED | 候选 [RETRY_SAME_KEY, MANUAL_REVIEW]；重试前当前复核 | 保持 UNKNOWN，允许原 command 同键重试 | retry_idempotency_key 必须等于原键；复核失败拒绝/人工 |
| 可信执行失败 | 记录 FAILED 回执，候选 []、next_action=null | FAILED | 失败不证明所有域都无副作用；Saga 按权威阶段处理 |
| 查询后仍 UNKNOWN/仅 accepted、查询错误或无法验证 | 候选仅 [MANUAL_REVIEW] | MANUAL_REVIEW，持久 queue_ref 与原因/已有证据 | 不盲重试，不直接补偿 |
| 外部无幂等/查询 | QUERY_SOURCE 通过可信台账/对账路径核实；无法确认人工 | MANUAL_REVIEW | 台账空白不是未执行证据；拒绝无人值守高风险写入 |

“记录成功”是事实提交，不混入 UNKNOWN 的三个候选动作。确认未执行后仍用 UNKNOWN 表示未终结；重试重新走 AUTHORIZED/执行复核，此恢复边由可信 NOT_EXECUTED 守护，不自创状态。

本次记录一次完成的查询仍无法确认即人工；查询内部可有界重查，预算/退避为建议基线，不能无限隐藏 UNKNOWN。ManualReviewEntry 保存 Context、queue_ref、command/saga 引用、MANUAL_REVIEW、reason_ref、last_error、证据、时间、次数；队列与人工状态同 owner 本地事务持久化。人工批准本身不能证明执行成功；需权威证据或适用的新命令。非法/无法处理的事件和凭证沿用 P1.5 DLQ，不静默丢弃或伪造成功。

## 6. Saga 步骤账与补偿顺序表

Saga 原样复用 §12：RUNNING → SUCCEEDED；失败后 COMPENSATING → COMPENSATED 或 MANUAL_REVIEW。PHYSICAL/ACCOUNTING 为域分类；shipped/not_shipped/posted/not_posted 为阶段分支标签。

| 步骤账字段 | 保存/验证要求 |
| --- | --- |
| step_id / domain / object_id / expected_version | 可信计划展开，权威对象与版本 |
| pre_state_ref / pre_state_hash | 执行前保存前置事实，正文仅受控引用/hash |
| command_id / command_key / command_status | 原 command/键/状态，Task 不替代 |
| started / execution_credential / authority_receipt | 未开始/已开始分离；开始留凭证，成功靠回执 |
| compensation_supported / compensable_action_ref / compensation_permission | 能力不足显式 false/null；权限只是保存的证据，执行再复核 |
| is_shipped / is_posted / stage_evidence_ref / branches / selected_branch | 权威最新阶段；四分支显式存在 |
| compensation_required / compensation | 按冻结业务口径判断适用；必要补偿有新 command/键/权限复核/回执 |
| manual_queue_ref | 失败、不能确认或不能补偿时持久人工 |

recovery_order 固定 PHYSICAL 第一组、ACCOUNTING 第二组，各组 step_refs。L2 核对所属域、唯一性、引用覆盖与实际时序，不能只排序展示。账务恢复开始前 physical_verified_and_restored=true 且有权威证据；没有实物步骤也需明确不适用证据，不能空数组自动通过。

| 顺序 / 权威阶段 | 补偿分支与要求 | 后续条件 / 失败 |
| --- | --- | --- |
| 1. MES/WMS 未发货 | not_shipped：查实物并按冻结动作恢复，取得恢复后证据 | 完成实物确认才允许账务 |
| 1. MES/WMS 已发货 | shipped：显式阶段处置，不能套普通可逆库存动作 | 缺权限/支持/冻结动作人工，真实动作待冻结 |
| 2. ERP 未过账 | not_posted：核对过账/核销事实，确认无需冲销或执行适用新动作 | 不编造账务冲销成功 |
| 2. ERP 已过账 | posted：实物确认恢复后走冻结的账务冲销业务分支 | 新批准、命令、键、回执，不直接通用冲销 |
| 原命令 UNKNOWN | 先走 UNKNOWN 查询/同键/人工 | 禁止直接补偿 |
| 补偿失败 | Command/Saga 适用 MANUAL_REVIEW，持久人工队列 | 不谎报 COMPENSATED |
| 补偿超时 | 补偿 command UNKNOWN，以自己的原补偿键查询 | 无法确认人工，不生成新补偿键 |
| 所有必要补偿完成 | 独立验证每条必要补偿 SUCCEEDED、实物证据完整、无 UNKNOWN | 才可 COMPENSATED；不需要补偿须有不适用证据 |

Step 四个 branches 必须存在。未冻结、不适用或需现场处置的分支可 action_ref/permission=null、manual_required=true，不能伪造自动补偿。选择依权威阶段，实际执行前再核阶段，防规划后已发货/已过账。flags 是投影，不能替代其权威引用内容核验。

补偿是新业务动作：compensation.command_id 不等于原 command_id，compensation.idempotency_key 不等于原 command_key；补偿自己重试/恢复仍用自己的同一键。补偿完整走规范化/策略/批准/持久化/执行复核/Tool/adapter/回执管道。原成功回执不是补偿成功回执，不用数据库 rollback 表达跨系统恢复。

## 7. 取消语义表

| 步骤观察 | 取消处理 | 保留事实 / Task 投影 |
| --- | --- | --- |
| 未开始，含 ACCEPTED/AUTHORIZED | owner CAS stopped_before_start=true，阻止启动 | 不新增 Command CANCELLED，保留原账 |
| 开始/取消并发 | Transaction owner 开始门禁/CAS 决定先后 | 取消赢则不开始；开始赢则按已开始 |
| 已开始，EXECUTING/UNKNOWN | stopped_before_start=false、confirmation_required=true，查询旧 command | UNKNOWN 不直接补偿；Task RUNNING/WAITING_HUMAN |
| 已完成有副作用 | 保留回执，确认后适用新补偿 | 不能用取消覆盖成功/删除凭证 |
| 无法确认或补偿失败 | 持久人工队列 | Task WAITING_HUMAN，Command/Saga 保留真实状态 |
| 所有已开始效果确认、适用补偿验证 | 可投影 Task CANCELLED | task_cancelled_is_reversal=false，不假定外部事实消失 |

Cancel intent 与 control outbox 同本地事务。Transaction 消费取消事实并用自身 CAS 约束开始；control-plane 不跨 owner 改命令表。取消 Result 的 business_success=false/NOT_CONFIRMED 是避免取消响应被当过账证据，原命令真实 posting/业务结果仍查 Transaction 回执。已开始无需补偿也须权威确认及冻结的不适用口径，不能仅置 flags=true。

## 8. ToolSpec、权威回执与审计

P3 引用 P0 ToolSpec，三个能力位显式必填布尔。任一 false，Admission 强制 unattended_high_risk_write_allowed=false、adapter_ledger_required=true、serial_object_lock_required=true、manual_reconciliation_required=true。三项 true 仍需 Policy/审批/权限/版本及上线门禁。台账不能将不存在的原生能力伪装为 true。

P1.5 回执 Schema 已支持 NOT_CONFIRMED/NOT_APPLICABLE/POSTED，business_success 与 posting_status 分离；**当前 P1.5 运行行为恒 NOT_CONFIRMED，不能算 P3 过账已实现**。P3 复用该回执，仅独立验证的权威回执驱动 SUCCEEDED，POSTED 另有权威过账证据/冻结核销口径。View 和回执的租户、命令、键/hash、来源、源版本、business_success/posting/evidence 必须一致。

普通审计/日志仅受控引用/hash和脱敏元数据；payload、前置状态、凭证正文进入 ACL 受控存储。没有新契约示例；静态样本 demo 标识只用简报允许值，时间全 UTC Z。Error/reason 不含敏感正文。

## 9. L2 实现约束清单

### 必须

- 保持锁定基线；新增契约按登记归属，统一既有分层/认证/Error，无新角色或生产错误码。
- 全部写入口含 P0 强制可信规范化/hash、Policy/审批、命令持久化、执行复核、Tool 受限调用、adapter、权威回执。
- 幂等键 tenant 域持久唯一；同键同绑定返回原命令/当前结果，异 payload 409；恢复不换键。
- 批准独立、绑定不可变、CAS 单一有效决策；旧/过期批准、payload 变化、撤权、对象/策略版本变化拒绝，给明确脱敏原因。
- 持久 lease 与对象范围单调 fencing；旧 worker 不能提交/派发；CAS expected_version；锁过期先查事实。
- 先持久化命令/步骤账/前置状态/审计意图/执行凭证再调用；回执/状态/outbox 同 owner 事务，跨系统无原子承诺。
- UNKNOWN 先查源，只有可信未执行才能同键重试并再复核；无法确认人工，禁止直接补偿。
- Checkpoint 查既有 command，已成功不重跑；晚到凭证独立可信处理。
- 补偿为新命令/键/回执且当前权限复核，先实物后账务，显式阶段分支，失败人工、不伪报 COMPENSATED。
- 取消仅阻止未开始步骤；已开始保留事实，确认及适用补偿；开始/取消 CAS 仲裁。
- ToolSpec 无能力显式 false，缺失/未知 fail-closed，拒绝无人值守高风险写入。
- 唯一权威回执驱动成功；过账证据与业务成功分离；Task/Run 不能推导已过账。
- 跨字段相等/时间先后/范围/分支/引用内容在执行点强制，Schema flags 不作权威证明。
- 依赖失败拒绝或持久等待；非法消息/凭证 DLQ/人工，不能静默丢弃。
- Mock 故障验收通过再进入已冻结 sandbox；缺真实依赖不编造上线能力。

### 建议基线

- 沿用已有 owner 存储、P1.5 outbox/inbox；持久 generation 配合显式 CAS。
- canonical 算法与 fingerprint 版本化，Schema 一起绑定；引用内容不可原地更新。
- 查询有界退避、补拉/对账周期、lease/续租/时限显式配置。
- Mock adapter 确定性注入成功丢回执、未执行、查询不可用、版本冲突、已发货/已过账、补偿失败。
- API/UI 显示状态来源/更新时间/command/回执/posting 状态，人工处理留下权威续处置证据。
