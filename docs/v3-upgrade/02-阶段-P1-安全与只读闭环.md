## 1. 权威边界与交付物

packages/contracts/openapi/p1.openapi.json 为新增 OpenAPI 3.1.0；与 p0 并存，统一 Context、后端类别、认证受众及 Error 从 P0 引用。六个新 Schema 描述分级、治理、审计、Vault、来源和只读结果，JSON Schema 使用 draft 2020-12。

tests/contracts/test_p1_contracts.py 仅使用标准库和 pytest，文件读取范围为 packages/contracts/。它锁定 P0 OpenAPI 与 11 个既有 Schema 的原始字节 SHA-256；期望哈希是本次开工前读取并计算的常量，不在测试运行时重新生成基线。不得通过重新格式化、换行转换或更新哈希掩盖 P0 改动。

P1 没有新增任务状态、错误码目录或队列状态。布尔治理结果是检查事实，不是新的生命周期。HTTP 错误复用 §10.2：400/422 结构或参数，401/403 身份权限，409 幂等/版本，429 预算，503 依赖不可用。404 沿用 P0 的待冻结声明；不得通过差异响应暴露跨租户对象存在性。所有失败引用同一 error.json，Error.code 的业务目录仍待冻结，message/details 只能脱敏。

本简报有关“批准外部模型域”的开工决策用于确定 API 前缀，不构成数据域合并授权。上位 §14.1 仍区分企业 IT 本地域与批准外部模型域；enterprise_cloud/VPC 属非本地后端，不能接收 C3/C4。公网 VPS、DMZ 入口与名称中含“本地”的云实例都不能自行取得本地域资格。

接口名称为本次 P1 细化基线，行为及 owner 受上位 §3/§4/§6/§10/§13 约束。内部服务身份必须核验用户委托范围。

上述同步操作仅返回 200 的成功形状与显式错误响应，不新增 202 队列协议。GET 使用 P0 的必需 X-Context；path.task_id 必须等于 Context.task_id。请求/结果的顶层 tenant_id、Context.tenant_id 及可信身份 tenant 必须相等。工厂和 task 在本次工厂只读链路必需，不能以默认值补全。

原有受理、决策、运行、业务快照、只读工具和模型调用继续使用 P0 的 tasks、decisions、runs、contexts/query、tool-requests、model-invocations。分类和出域判断不可成为旁路模型调用端点。即使先取得 permit_invocation=true，实际 model-invocations 仍需按当前内容、身份、策略和模型版本重做治理，禁止把早期判定当可重放票据。

只读回答接口只返回引用。解析 answer_ref/citation_ref/snapshot_ref/restored_ref 仍是受 ACL 与数据域约束的读取。C3/C4 正文不得经 DMZ/公网渠道中转；未冻结同批准本域的回传路径时只能拒绝或在既有任务流程等待，不以“内部 API”或“只读”为理由放行。引用元数据也必须按数据等级保护。

## 4. 出域判定矩阵

模型类别直接复用 P0：local、enterprise_cloud、public。local 指**批准企业受信任本地域**，enterprise_cloud 指已批准企业云/VPC，public 指已登记公网模型。下表“允许”均为候选许可，必须同时满足身份、用途、最小化、DLP、模型白名单、健康、版本及输出治理；任一缺项即拒绝。

| data_class | local | enterprise_cloud | public |
| --- | --- | --- | --- |
| C0 | 允许：公开性来源可追溯，扫描通过 | 允许：已登记、策略许可 | 允许：已登记、策略许可 |
| C1 | 允许：tenant/用途限制、最小化、DLP | 允许：政策及用途许可 | 允许：政策及用途许可 |
| C2 | 允许：最小化、DLP、授权 | 允许：批准匿名化/Tokenization 及可信复核通过；仍保持 C2；否则拒绝 | 拒绝 |
| C3 | 允许：只在批准本域处理 | 拒绝 | 拒绝 |
| C4 | 允许：本地 + 任务白名单 + 专门批准 + 无密钥材料 | 拒绝 | 拒绝 |
| 未知/缺失 | 拒绝：不能建立有效分级上下文 | 拒绝 | 拒绝 |
| 任意等级且本地后端故障 | 拒绝或排队；不得自动公网降级 | 不作为故障自动回退目标 | 不作为故障自动回退目标 |

后端类别从登记模型元数据取得，不能由请求者选择标签把外部后端伪装成本地。C2 是否批准变换由规则版本、复核及内容扫描共同决定；仅替换姓名不够。C3/C4 即使 Tokenization 后仍无非本地许可。GPU预算、时延、任务路由或模型置信度都不能放宽此矩阵。

p1-governance 用 permit_invocation=false 表达禁用调用；敏感非本地、失效检查、C4 不具批准、密钥材料、backend_healthy=false、local_backend_failed=true 都不能产生许可，public_fallback 固定 false。排队通过既有 Task/Run 状态与安全引用保留，具体状态映射、恢复与超时协议待冻结；未冻结时返回统一拒绝或 503，不用 200/202 假称已调用或已排队。

C3/C4 的原始数据、向量、Memory、Vault、备份和处理节点必须同等级留在批准本域。包括 embeddings、遥测、错误收集、回放和日志传输在内的网络出口必须受控。P1 对日志/审计/验收证据采用更严格规则：只允许安全摘要引用、引用、哈希和版本，不把上位文档允许的受控原文证据存储当作本次日志或验收证据入口。

## 5. §4.3 治理有序环节

| 顺序 | 原文环节 | L2 必须执行的控制 | 可定位契约 |
| --- | --- | --- | --- |
| 1 | 身份与租户校验 | 可信认证与登记 tenant，内部调用核验委托范围 | identity_tenant / identity_verified |
| 2 | 工具/检索访问范围 | 工具/查询白名单，tenant/工厂/岗位权限，RAG 候选召回前过滤 | access_scope / access_scope_verified |
| 3 | 输入及派生上下文分类 | 完整上下文逐项分级并取最高；每次返回重新分级 | classification / p1-classification |
| 4 | 最小化与脱敏 | 最小化正文/附件/自由文本；Tokenization 不自动降级 | minimization / minimized |
| 5 | DLP/出域策略 | 扫描可重识别字段与不可信内容，执行判定矩阵 | dlp_egress / dlp_passed |
| 6 | 模型白名单 | 绑定登记模型/版本/后端、tenant、用途与任务许可 | model_allowlist / model_allowlisted |
| 7 | 调用 | 仅经 P0 model-invocations 调用；故障不走公网兜底 | invocation / permit_invocation |
| 8 | 输出Schema/泄露扫描 | 验证输出结构并阻断未授权原文/令牌；不得提前流式回传 | output_scan / output_schema_passed、output_leak_scan_passed |
| 9 | 本地授权的 Token 恢复 | 在本域核验 tenant、用途、有效期和消费者权限 | local_token_restore / RestoreResult |
| 10 | 用户/工具消费 | 消费时再次授权；受控恢复内容不得转送未授权消费者 | consumption / consumer_acl_verified |
| 11 | 分级审计 | 追加只含安全引用/哈希/版本的事实记录，不能记录原文或 Token 值 | graded_audit / p1-egress-audit |

该顺序不能提前调用、先输出后扫描或先恢复后扫描。请求在某步失败便停止后续消费，并记录失败步骤的安全证据引用；未执行的后续步骤不能伪造通过。审计持久化意图可以预先建立，但最终记录仍按上述治理事实形成。审计存储故障不得转成安全绕行，可靠性策略待冻结。

Vault 私有 Mapping 只在 security 本地域保存，entries 包含 token 与 original_ref；没有查询/导出映射 API，任何响应均不返回映射原值。令牌有效期在恢复时根据可信 UTC 当前时间验证，不能仅检查 expires_at 的字符串格式。模型输出中的未授权令牌不能成为任意原值查询入口。授权恢复后的内容继承等级，并在消费前再核对消费者范围。Token 格式、加密密钥管理、最大有效期和销毁策略待冻结。

## 6. 只读问答链路与来源可追溯字段表

入口校验 → P0 Task API → Rules/Jev → Hermes → Harness 业务上下文 → Tool Gateway 已登记只读工具 / 受 ACL 约束 RAG → 每次上下文返回重新分级 → P0 Model Router 治理调用 → 输出扫描 → 本地授权恢复（需要时）→ 同批准域授权消费者 → 渠道回传与轨迹。

manufacturing-core 主责知识 ACL、权威投影与来源；tool-gateway 主责只读工具白名单/参数/返回过滤；security-gateway 主责治理与 Vault；control-plane 保存任务与回答投影；hermes-runtime 只编排，不能取得数据库密钥或自行批准可见性；trajectory-eval 保存受控索引。遵循 §13 owner 边界，不跨 owner 直接写表、join 或建外键。

**检索前**将可信 tenant、工厂、岗位 ACL 施加于向量/文本/对象候选集、缓存和索引分区；不能先全库召回再靠返回过滤或 LLM 判断。**返回时**重新核对来源及引用目标的当前 ACL、版本和有效期，再重分级。检索期间权限撤销也必须阻断消费。来源 metadata、chunk、Memory 与对象引用都不跨租户；Knowledge/Memory 不隐式复制。

| 字段 | 必需语义 | owner / 验收用途 |
| --- | --- | --- |
| tenant_id | 从可信身份取得并与任务、来源、引用目标一致 | 全链路串联与隔离 |
| factory_id | 来源工厂与授权范围；本次工厂问答不得为空 | manufacturing / 工厂 ACL |
| task_id、trace_id | 每条返回来源关联当前任务与追踪 | control、trajectory / tenant-task-trace 串联 |
| source_system | 已登记权威源的安全标识，不是任意 URL | manufacturing / 一数一源 |
| source_id | 源对象的受控引用标识，不含正文 | manufacturing / 回溯对象 |
| source_version | 权威事实/文档版本，不以“最新”替代 | manufacturing / 重现来源快照 |
| occurred_at | 事实发生时间，UTC ISO8601 Z | 来源时间与新鲜度 |
| received_at | 平台收到来源的时间，UTC ISO8601 Z | 区分发生与接收 |
| data_class | C0–C4；来源返回后可信重分级 | security / 出域最高等级 |
| quality_status | 复用 P0 的登记目录，具体取值待冻结 | manufacturing / 可信投影质量 |
| citation_ref、snapshot_ref | 当前授权主体可解析的本地域引用 | source_version 对应快照及回答关联 |
| valid_until | 快照有效期，实际时效在读取/消费时核验 | 防止过期业务数据成为回答依据 |
| acl_check | ACL 引用/版本、检索前三级过滤和返回再校验均通过 | 检索执行证据；不由 LLM 自报 |
| Answer.answer_ref | 扫描通过的受控回答引用，无原文审计副本 | 同域消费者回传 |
| Answer.classification、audit_refs | 回答输出等级、完整输入分级、审计引用 | 等级继承与来源-调用-回答关联 |

sources 中任何一项高于 Classification.data_class 都不能构成成功回答；来源还必须存在于分类 inputs 的实际引用集合中。来源版本/时间、tenant/task/trace 一致性及引用内容哈希由 L2 验证，不是 schema 字段存在便算通过。无授权来源时 QueryResult 可返回空 sources；Answer 成功形状至少一条来源。没有来源的结论不得包装成可追溯业务事实，未完成或无来源的读取语义待冻结。

所有协议时间使用 P0 UtcTimestamp，UTC ISO8601 且 Z 结尾。数量/金额若后续扩展，必须复用 string + pattern 的 Decimal，并冻结精度、单位、币种及换算版本；当前 P1 不新增数量/金额业务字段。示例标识只用 tenant-demo / factory-demo / user-demo / employee-planning / task-demo / trace-demo；不得填写真实地址、账号或密钥。

## 7. L2 实现约束清单

### 必须

1. 保留 P0 契约的原始字节，新增 P1 文件；不改动 services 或 tests/p0_runtime 是本次 L1 产出边界。实现阶段 L2 按 owner 实现功能，不能要求 L1 改业务实现。
2. 仅在既有 /api/v1/ 和 /internal/v1/ 暴露表中新增接口，复用认证受众和统一 Error；禁止新增接口层及平行模型调用入口。
3. 未知 tenant/工具/等级/模型/目录、登记依赖失败均 fail-closed；请求值不能覆盖认证、岗位 ACL、数据分级、后端登记或扫描事实。
4. 全量上下文分类、最高合并、输出继承；Tokenization 不自动降级，C3/C4 无非本地调用，C4 密钥材料不入模。
5. 每次实际调用重做治理，后台重试、SDK fallback、预先 embedding、批处理、遥测及引用解算同样受约束；本地故障拒绝或安全等待，不调用公网。
6. ACL 必须在召回前过滤 tenant/工厂/岗位，返回后及消费时复核；与缓存、向量、Memory、对象路径、备份的隔离一致。
7. 来源包括版本、发生时间、等级及 tenant/task/trace；来源引用及版本真实存在，与分类 inputs 和实际回答绑定。
8. 输出 Schema/泄露扫描先于 Token 恢复及消费；扫描失败不返回 Answer/RestoreResult 成功形状，不提前流式输出未扫描内容。
9. Vault 私有映射只保存在批准本域，按租户、用途、有效期隔离；未知用途/消费者、过期、跨租户或未经授权恢复必须拒绝。
10. 日志/审计/验收证据只有安全摘要引用、引用、哈希、版本及治理元数据，禁止敏感原文、原始输出、令牌值、恢复值、密钥和任意 payload。
11. 服务 owner 与源系统主责不变；只读链路不产生业务写命令，不复制 Knowledge 到 Memory，不让模型判断最终可见性。
12. P1 静态门禁不依赖任何实现、网络或 DB；运行验收另行执行，不能以静态通过宣称 P1 完成。

### 建议基线

- 数据库 RLS 是应用权限检查的第二道隔离；高敏租户按需要独立实例和密钥域。
- 引用采用不含业务原文的稳定不透明标识；来源、内容规范化哈希、模型/分类/策略/ACL 版本绑定可复核。
- 引用快照与恢复结果留在本地受控存储，Vault 使用与普通日志不同的数据库角色和密钥；拒绝结果保持跨租户响应一致。
- 本地持久化审计意图及 outbox 补送；故障演练同时观察模型连接器、egress 代理与出口计数，审计不能替代真实出网证据。
