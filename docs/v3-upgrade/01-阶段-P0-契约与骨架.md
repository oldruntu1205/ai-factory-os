# 01 阶段 P0：契约与骨架 SPEC

唯一架构依据：桌面文件 AI_Factory_V3.0_系统架构.md，版本 3.0.0，日期 2026-10-04。接口表来自 §10.1，公共字段与命令来自 §10.2，事件来自 §11，状态来自 §12，健康接口来自 §14.2，完成条件来自 §16。本文不新增架构 owner、业务路径或业务错误码语义。

本次 L1 交付只包括 OpenAPI、JSON Schema、静态门禁与本文。L2 在 services/ 实现八个运行单元，与既有 backend/ 并存。既有 backend 的在产能力与 64 PASS 测试基线作为已提供事实，本次不重新探索或验证。创建业务实现、迁移、Compose 和 ADR 是 L2 的任务。

## 1. 交付与验收边界

- packages/contracts/openapi/p0.openapi.json：OpenAPI 3.1.0，15 条业务接口和两条原文健康接口，统一请求、响应、错误与认证边界。
- packages/contracts/schemas/：2020-12 JSON Schema；common-context、error、command、decision-result、event-envelope、tool-spec、task、command-status、service-manifest，以及 api-models 与 state-machines 两个定义容器。
- tests/contracts/test_p0_contracts.py：标准库 + pytest 静态主门禁，只读上述两个目录，不导入 backend/services、不访问网络、不连接 DB。
- 本文：L2 实现边界与 L3 验收依据。

契约文件统一采用 JSON 编码，也是 YAML 1.2 的合法子集；门禁无需 YAML 依赖。所有引用在仓库内相对解析，禁止外部 $ref、绝对文件路径、目录逃逸与悬空引用。$schema 的标准元 Schema URI 仅是方言标识，不触发网络读取，也不是部署域名。

静态门禁通过只证明契约自洽。P0 完成仍须同时满足原文：**核心服务可启动；拒绝未知 tenant/工具；Mock 闭环可追踪。** 本次未执行测试，未出具运行验收结论。

## 3. 公共 Context 与封闭性

tenant_id / factory_id / actor_id / employee_id / task_id / trace_id / data_class / schema_version / deadline_at 的键全部显式必填。factory_id 在不适用时显式 null；employee_id、task_id 在尚未绑定时显式 null。Command 的 factory/employee/task 及 Task 投影的 task_id 必须非空。无工厂作用域不得执行工厂动作。

tenant_id 和 actor_id 必须与可信身份及委托范围核对，不能采信模型或渠道自填身份。unknown tenant、unknown tool、unknown data_class、登记服务不可用均拒绝。tenant/tool 的 x-registry、x-on-unknown、x-on-unavailable 及每个业务操作的 x-required-enforcement 是 **L2 必须执行的语义契约**，不能只让 JSON Schema 校验器忽略这些扩展。通用 JSON Schema 本身不能证明 ID 已登记。

所有枚举型、契约型对象使用 additionalProperties: false。独立业务对象显式持有必填 tenant_id；嵌套 payload、能力配置、回退等辅助对象声明 inherited，继承所属 tenant，不能独立存储或变成全局对象。嵌套引用对象仍携带 tenant 时须与外层完全一致。静态门禁验证引用图中 inherited 对象的归属。

全局对象白名单只有四项：

| 对象 | 原因 |
| --- | --- |
| error.json 根对象 | 身份拒绝时未必存在可信 tenant，仅 trace 与脱敏诊断 |
| error.json 的 Details | 统一错误诊断，不含任意业务正文 |
| service-manifest.json 根对象 | 全局运行单元和 owner 配置 |
| api-models.json 的 Health | 全局运维状态 |

C0–C4 与 R0–R3 使用封闭枚举，无默认等级。ModelInvocationRequest 对 C3/C4 的 model_backend 强制 local；backend 值还须与登记模型元数据核对，客户端填 local 不能证明实际本地。local 指批准企业数据域，不能把任意云主机标成本地。未知等级结构拒绝；混合上下文及输出继承最高等级，本地故障不得切公网。

协议时间只接受 UTC ISO8601 的 Z 表示；具体业务数量/金额引用 Decimal 的 string + pattern，不接受 JSON number。expected_version、aggregate_version 等是离散版本序号；confidence 是无量纲校准值，不是数量或金额。

## 4. 命令、工具、事件与恢复

Command 完整包含 §10.2 示例字段，全部列入 required；schema_version 与 tool_id/tool_version、payload_hash、policy_evaluation_ref 明确补足公共 Context 与可信绑定。approval_ref 必须提供，免审批时可显式 null，但必须存在权威 Policy 判定凭证。示例只支持 pmc.dispatch.publish 的 schedule_version 结构，仅用于 Mock，不代表生产排程发布授权。

可信规范化服务必须计算并复核 canonical payload_hash，绑定工具版本、对象、tenant/actor、approval、动作和策略版本。Tool 与 Policy 先规范化、判定，再构造供 Transaction 持久化的 Command；PolicyEvaluateRequest 不要求尚未产生的判定凭证。同幂等域必须包含 tenant；同键同规范化内容返回原 command_id 与当前状态，不同内容409。AUTHORIZED 到 EXECUTING 之前再次验证当前权限、批准有效性与对象版本。

ToolSpec 包含全部上位字段。input_schema/output_schema 是封闭的仓库相对 SchemaBinding，不是任意开放 JSON 对象；L2 必须解析并验证真实内容、版本和 hash。idempotency_support/status_query/compensation 为必填布尔值，无能力则 false。工具输入、上下文、模型输入及事件正文在 P0 可使用受控引用；引用解析后仍须执行登记 Schema、tenant ACL、分级及有效期检查，不能以引用替代验证。

Decision 的 route/action/category/reason_code/fallback 属于版本化有限目录，具体值待冻结，不在本文发明枚举。P0 使用显式登记的 Mock 目录，未知值或目录不可用拒绝；示例中的 route-demo 等只是占位标识。无有效 calibration_version 时 confidence 必须 null。任何置信度和自然语言解释均不能赋予执行权限。

EventEnvelope 必填 §11 字段与 payload；本次 payload 是 payload_ref/payload_hash 的封闭最小化引用对象。首期 event_type 逐项使用 §11 目录，实体质量、aggregate 与真实事件 payload 的目录待冻结。原始内容不得放入普通日志或未经批准的数据域。

事件为至少一次投递：同 owner 状态/outbox 同事务，投影/inbox 同事务；按 tenant+aggregate 版本收敛，迟到不覆盖、重复不重放。Checkpoint 持久化程序位置、上下文引用、待执行命令和已完成回执；恢复先查既有 command，使用 CAS、租约及 fencing token。

UNKNOWN 必须先查询源系统命令/凭证；确认未执行才以原幂等键重试，禁止换键或直接补偿。取消 Task 不等于撤销副作用。Saga 补偿是新的业务动作，按实物与账务阶段处理，失败进入 MANUAL_REVIEW。

## 5. 状态机表（§12 原文）

| 对象 | 核心状态 | owner |
| --- | --- | --- |
| Task | ACCEPTED → RUNNING → WAITING_APPROVAL/WAITING_HUMAN → SUCCEEDED/FAILED/CANCELLED | control-plane |
| Run | CREATED → RUNNING → CHECKPOINTED/WAITING → COMPLETED/FAILED/CANCELLED | hermes-runtime |
| Command | ACCEPTED → AUTHORIZED → EXECUTING → SUCCEEDED/FAILED/UNKNOWN；可进入MANUAL_REVIEW | transaction |
| Saga | RUNNING → SUCCEEDED；失败后COMPENSATING → COMPENSATED或MANUAL_REVIEW | transaction |
| Edge release | DRAFT → SCHEMA_FROZEN → CALIBRATED → SHADOW → APPROVED → ACTIVE → REVOKED | release registry及现场节点 |

state-machines.json 与门禁硬编码表逐项一致；Task、Run、Command、Saga、EdgeRelease 的 status 均直接引用此表。上位表是核心流程示意，不提供完整转换矩阵；本文不擅自补写跳转、撤销或回退状态，生产迁移守卫需由对应 owner 冻结。

Task 保存编排投影，Command 的副作用状态归 Transaction；状态响应显式包含 status_source 与 updated_at。只有权威回执才能驱动业务成功，ACCEPTED、AUTHORIZED、UNKNOWN 不能显示已过账。

## 6. 错误码表

统一错误体：code / message / trace_id / retryable / details 全部必填；details 封闭且脱敏，可为空。业务 code 字符串目录待冻结，本次只约束非空结构与原文 HTTP 分类，不赋予 Mock 占位 code 生产语义。

| HTTP | 原文语义 / 冻结边界 |
| --- | --- |
| 400 | 结构或参数错误 |
| 401 | 身份拒绝 |
| 403 | 权限拒绝；未知 tenant/工具、禁止路由必须拒绝，具体业务 code 待冻结 |
| 404 | 按任务要求预留标准响应；上位文档未定义业务语义，待冻结 |
| 409 | 幂等或版本冲突 |
| 422 | 结构或参数错误 |
| 429 | 预算限制 |
| 503 | 依赖不可用；不能证明外部写入未执行 |

每个操作显式引用以上标准响应及统一 Error。401/403/404 的脱敏与对象隐藏策略不得泄露跨租户对象存在性。retryable 不允许被 SDK 解读为无条件重发副作用：命令超时/5xx仍必须查状态，不能换新键。

## 7. L2 实现约束清单

### 必须

- 在 services/ 建八个运行单元；security/decision/hermes/tool/transaction 保持独立进程与身份；ServiceManifest 示例为 Mock 配置形状，L2 生成真实部署 manifest，不能用示例证明服务已运行。
- 独立 schema、迁移目录与 DB role；禁止跨 owner 写表、join、外键。共享 packages 仅契约与纯领域约束，不能共享 repository 或 DB 连接。
- 可信认证、tenant/factory/岗位与委托范围核对；服务身份不自动继承用户业务权。未知租户/工具/动作/等级及缺登记配置拒绝。
- 每次模型调用走 Security；输入与派生上下文重新分类，C3/C4只批准本地，C4任务白名单与专门批准，C2批准变换不自动降级，敏感日志/向量/Memory/备份不得跨域。
- 工具白名单、实际参数及返回 Schema 校验、风险可信计算；执行点复核 Policy/批准/对象版本；业务 adapter 写入口只允许 Tool 的受限身份。
- 命令先持久化再202；可信 hash、tenant 幂等、expected_version、payload_version、审批绑定和 UNKNOWN 查询语义不可省略；无状态确认能力不开放无人值守高风险写入。
- 状态源、回执、outbox/inbox、CAS/fencing 与检查点恢复不把受理当成功、不重放已成功步骤；策略/Transaction 不可用不得绕过。
- 所有服务提供原文 health 路径；readiness 核实关键依赖、策略版本和积压，不能固定返回 true。依赖不就绪不得宣称 ready；不可用为503。
- Edge 影子写路径物理/网络禁用；本地 Schema/校准/场景许可/互锁先于置信度，至少连续14天加覆盖和指标证据才可晋级；设备安全始终优先。
- 待冻结生产依赖未填实只用 Mock 或获准只读；交付标明环境、版本、退出码、脱敏回执与剩余依赖，不宣称生产验收。

### 建议基线（可不改变边界地通过 ADR 调整）

- PostgreSQL、Redis、本地对象存储、受 ACL 的向量后端和持久化消息代理；每 owner 独立 schema/迁移/角色不属于可取消建议。
- DB RLS 作为第二道隔离；应用身份校验仍为必须。
- Docker Compose 开发与 Mock；生产容器、独立身份、受限密钥挂载；不强制 Kubernetes。
- 中心 API/Edge 优先 Python，Web 优先 TypeScript；具体版本与 Hermes/Jev 适配由 L2 在 P0 选型 ADR 冻结。
- 0.70/0.92 为 Edge 初始校准基线，0.92 属人工复核；生产逐场景阈值仍待冻结，不把该区间固化为全部产线许可。
- 消息产品、向量后端、实际依赖版本在 L2 的 P0 ADR 冻结；manifest 的5.000秒是明确 Mock 示例，不能据此产生生产 SLO。

## 9. L3 可执行验收与证据

静态主门禁由 L3 从仓库根运行（本文只给指令，L1 未执行）：

~~~text
backend\.venv\Scripts\python.exe -m pytest tests/contracts/test_p0_contracts.py -q
~~~

门禁逐项验证：文件解析与方言、本地引用、15+2 精确目录、显式统一4xx、封闭对象与 tenant 引用图、C/R枚举、五类状态机、命令 required/hash 声明、八个 owner、UTC/定点表示与反例。只覆盖本包所用 Schema 关键字；完整 OpenAPI 工具链与代码生成由 L2 选型，不能据此省略运行鉴权。

L2 实现后，L3 必须另行给出以下运行证据，才能认定 §16 P0 完成；下表是运行验收断言，未冒充本次纯文件测试已验证：

| 场景 | 可观察断言 |
| --- | --- |
| 启动八个核心服务与 Mock 依赖 | 独立进程/身份、owner角色与迁移可启动；live200；依赖/策略不可用时 ready503，不创建新中心副作用 |
| 未登记 tenant、未登记 tool、身份与自填 tenant 不一致 | 明确4xx拒绝，未建立业务任务/命令或调用 adapter；日志只有 trace 与脱敏理由 |
| 可信 tenant 的 Mock 闭环 | 任务受理、decision、run、工具请求/Mock命令、回执与 trajectory 可按同一 tenant/task/trace 串联；仅权威 Mock 回执驱动成功 |
