# docs/handoff/ —— L2 交付证据

上游 §15 把本目录列为**交付证据**的落点；§18 要求每阶段提交：

> 代码与依赖锁、Schema/OpenAPI、owner 迁移、配置样例、启动/回滚步骤、
> 验证结果、已知限制、未决依赖及 ADR

## 它与 `docs/v3-upgrade/` 的分工

| 目录 | 放什么 |
|---|---|
| `docs/v3-upgrade/` | **设计与过程**：阶段 SPEC、总纲、交付报告、上游条款对照 |
| `docs/handoff/`（本目录） | **逐阶段交接证据**：给下一位工程师/评审人的"现在到哪了、怎么验、什么没做" |

两处都会提到同一件事（如"P5 未做"），但**口径不同**：
前者解释"为什么这样设计"，后者只回答"**接手要做什么**"。

## 一条纪律（不是建议）

本目录的内容**必须是可重跑的产物或可核对的清单**，不能是"我测过了"这类自述。

上游 §17 原文：

> 只在文档或单元 Mock 中通过**不等于**完成生产验收。
> L2 送审包必须标明 Mock、sandbox 或真实环境，提供**执行命令、版本、退出码、
> 关键状态**与脱敏回执。

所以每份交接记录都要能回答：**跑哪条命令、期望看到什么、实际看到了什么。**
