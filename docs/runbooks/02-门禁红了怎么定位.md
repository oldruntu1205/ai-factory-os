# 02 · 门禁红了怎么定位

## 门禁命令（**唯一完成判据**）

```powershell
cd "H:\制造业 AI 员工平台全量开发"
backend\.venv\Scripts\python.exe scripts\gate.py --stages p0,p1,p15,p2,p3,p4,assertions
```

只跑单个阶段更快定位：`--stages p3`。

> ⚠️ **必须串行跑**。门禁会起真实多进程集群（8 个单元，端口 8101-8108）。
> 同时跑第二次（前台 + 后台、或两个窗口）会**抢端口**产生**假失败**。
> 本项目已因此误判两次——一次还被误当成代码缺陷，实际是并发。

## 第一步：看是哪一步

门禁输出里每步有 `# 覆盖: …` 与 `# 退出码: N`。先定位到步骤名，再跑单阶段：

| 步骤名 | 对应套件 |
| --- | --- |
| P0 运行验收 | `tests/p0_runtime` |
| P1.5 运行验收 | `tests/p15_runtime`, `tests/p15_events` |
| 受控写入语义 | `tests/p3_transactions` |
| 端到端路由面 | `tests/e2e` |
| 管理后台状态契约 | `tests/web_admin`（内含 `node --test`，**零依赖**） |
| 基础设施清单 / ADR | `tests/infra` |
| A01–A14 断言覆盖 | `tests/assertions` |

## 现象 → 原因 → 处理

### 现象：`P0/P1 运行验收` 报红，但单跑就过

**原因**：几乎一定是**并发抢端口**（门禁起真实多进程集群）。
**处理**：先确认没有第二个测试在跑：

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -match 'pytest|gate\.py|-m services' } |
  Select-Object ProcessId, CommandLine
```

有就先清掉，再串行重跑。

### 现象：`N 个用例未声明它支撑的上游断言`

**原因**：在 `TAGGED_SUITES` 的目录里新增了用例但没标 `# Axx`。

**处理**：

- 若该用例**确实**支撑某条 A01–A14 ⇒ 在函数定义行尾加 `# A06`，
  并把它加进 `tests/assertions/assertion_inventory.py` 里对应断言的 `refs`；
- 若它描述的是**结构约束**（不是 V3 行为）⇒ 把该**文件**登记进 `UNTAGGED_SUITES`，
  并写明理由（无理由的豁免就是掩盖）。

**归属要核对**：跨租户隔离属 **A01**、过账结论属 **A14**、Guard 顺序属 **A09**。
本项目曾把跨租户用例错标成 A09。

### 现象：时间相关用例失败（`lease-expired` / `expired` / 过期）

**原因**：**不要先怀疑并发。** 先看是否"判定函数读了墙钟"。

本项目真出过：`transactions._lease_unexpired_static` 读 `time.time()`，
而 `review_command` 早已算好 `moment` 却没用上——
夹具用固定常量当到期时间，墙钟跨过那一刻就**永久失败**，
而表象像是在说"跑得快/慢"。

**处理**：判定函数应收**调用方传入的时刻**，不该调 `time.time()`。
修法是**改实现、不改测试**（夹具传 `now` 是对的，设计意图就是"判定只用传入的 now"）。

验证手法：传两个**极端时刻**，结论必须相反——

```python
assert tx._lease_unexpired_static(expires_at, moment=1_700_000_000.0) is True   # 2023
assert tx._lease_unexpired_static(expires_at, moment=4_100_000_000.0) is False  # 2100
```

### 现象：契约测试报红 `Additional properties are not allowed`

**原因**：你**给响应加了契约里没有的字段**。

**处理**：**读对接口 / 不加字段**，**不是改宽契约**。

实例：`command-status.json` 是 `additionalProperties: false` 只允许 16 字段；
P3 的权威事实（`authority_receipt` / `posting_status`）在
`p3-command.json#/$defs/View`，由 `GET .../execution-record` 返回。

### 现象：端到端路由面报红「这条路由注册了却打不到」

**处理**：按顺序查——

1. 该 owner 有没有对应的 service？（`OWNER_BY_SERVICE`）
2. `edge` owner 没有 service，靠 `routes_for()` 的 `EDGE_OWNER_SERVICE`
   并入 `manufacturing-core`——检查那段还在不在；
3. 方法是否登记错（400 且理由含"方法"）。

### 现象：`tests/web_admin` 被 skip

**原因**：本机没装 node。

**处理**：这是**不算通过**的状态，不是通过——
"A14 在后台侧未验证"必须与"已验证"可区分。装上 node ≥ 22 后重跑。

## 定位完别忘

```powershell
# 清理残留服务进程
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -like '*-m services.*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }

# 清 pytest 缓存
Remove-Item .pytest_cache -Recurse -Force -ErrorAction SilentlyContinue

# 确认没有临时探针脚本遗留
Get-ChildItem scripts -Filter "_*.py"
```
