# 03 · 新增接口（或字段）的完整流程

上游 §17 的断言是按**行为**写的，所以"加一条路由"不是加个函数就完了。
按下面顺序做，缺哪一步门禁都会在对应位置报红。

## 1. 先看契约，不先写代码

```powershell
cd "H:\制造业 AI 员工平台全量开发"
Get-ChildItem packages\contracts\openapi, packages\contracts\schemas
```

- 新增/修改**请求或响应形状** ⇒ 动 `schemas/*.json`（`additionalProperties` 是
  `false` 时**不能多给字段**）；
- 新增**路径** ⇒ 动 `openapi/*.openapi.json`，并在 `routes.py` 的
  `ROUTES_BY_OWNER` 里登记（含 `owner`）。

> **契约是判据。** 已发生过的教训：修一个 500 时"顺手把字段加全"，
> 结果被 `test_responses_conform_to_contract_schemas` 当场抓住。
> 正确修法是**读对接口**，不是改宽契约。

## 2. 登记路由时想清三件事

| 问题 | 影响 |
| --- | --- |
| 归哪个 `owner`？ | 决定它挂在哪个 service 上（`OWNER_BY_SERVICE`） |
| 要不要 `context`？ | `requires_context`；P1 契约的 Context 要求 `tenant/factory/task_id` **非空** |
| 身份受众是谁？ | `/api/v1` 面向用户、`/internal/v1` 面向服务账号、`/edge/v1` 面向现场 |

⚠️ **不要**给 P0 形状的响应加 P3 字段（反之亦然）。两种形状各有契约，
混进去就是违约。

## 3. 请求体字段：让 dispatch 兜住"缺字段"

`http.dispatch` 会把"缺**请求字段**"的 `KeyError` 转成 **400 `REQUEST_INVALID`**
（而不是 503）。判据是 `_is_request_field`——它对着 openapi 契约问
"这个名字是不是客户端该提供的"。

所以：**客户端该给的字段**直接 `body["x"]` 没问题（缺了会变 400 并点名）；
但**服务端内部字典**不要用同一形状，否则真缺陷会被吞成 400。

## 4. 补测试（按断言归属放）

| 你在验什么 | 放哪 | 标什么 |
| --- | --- | --- |
| 跨租户读取被拒 | `tests/p1_runtime` 或 `tests/e2e` | **A01** |
| 入参不合法不得 5xx | `tests/p2_runtime/test_input_robustness.py` | A14 |
| 受控写入/租约/回执语义 | `tests/p3_runtime` / `tests/p3_transactions` | A04/A05/A06/A14 |
| Guard 顺序、影子、spool | `tests/p4_edge` / `tests/p4_runtime` | A09/A10 |
| **结构约束**（可达性、清单一致性、ADR 格式） | `tests/e2e` / `tests/infra` | **不打 Axx**，登记进 `UNTAGGED_SUITES` |

**新用例必须声明断言**（行尾 `# A06`），并加进
`tests/assertions/assertion_inventory.py` 的 `refs`——
否则 `test_every_test_in_tagged_suites_declares_its_assertion` 报红。

## 5. 补变异（**这一步最容易被跳过，但不能跳**）

在 `scripts/mutate.py` 的对应 phase 加一条：

```python
(
    "描述这次注入的缺陷",
    "相对路径/文件.py",
    "原文（必须在文件里**唯一**出现）",
    "改成的样子（必须**语法合法**）",
    "用来抓它的套件路径",
),
```

- 原文**不唯一**会直接判失败（防止改错位置）；
- 变异后语法不合法会被判 `[无效]`（防止"因语法挂掉"被误记成"被捕获"）；
- 跑：`backend\.venv\Scripts\python.exe scripts\mutate.py --phase p3`
- 期望：`[捕获]`。若是 `[逃逸]`，说明**门禁没有牙**，回去补测试；
  若**结构上无法捕获**，就写成 `[已接受]` 并写明理由（不许假装捕获）。

## 6. 若新增了模块/目录

- 新目录里有用例 ⇒ 加进 `scripts/gate.py` 的步骤，并决定它是
  `TAGGED_SUITES` 还是 `UNTAGGED_SUITES`；
- 新服务单元 ⇒ 同步四处：`services/_kernel/routes.py` 的 `OWNER_BY_SERVICE`、
  `tests/p0_runtime/conftest.py` 的 `SERVICE_MODULES`/端口、
  `infra/deployment/manifest.yml`、`infra/compose/docker-compose.dev.yml`
  （`tests/infra` 会逐一核对，漏一处报红）。

## 7. 最后：写交接文档

`docs/v3-upgrade/handoff/` 下一篇 `P<阶段>-<主题>.md`，包含
**改了什么 / 怎么验证 / 怎么回滚 / 遗留风险**。
若做了有长期影响的取舍，另写一篇 `docs/adr/NNNN-*.md` 并登记索引。
