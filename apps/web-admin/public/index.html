任务结论

输入 task_id 查询。本系统没有"任务列表"接口（只有按 id 取单条）， 所以这里是精确查询而不是列表——这一点如实说明，不用假数据凑出一个列表。

命令与权威回执

这里才是「已过账」唯一能成立的地方。 任务视图里的编排状态不等于账务事实； 只有权威回执说 POSTED 才算过账（上游 §6 / A14）。 命令与任务的关联（command_refs）属后续阶段、当前尚未接线， 所以这里按 command_id 直接查——不伪造那条关联。

批准可决定性

输入 approval_id 查询。决定必须记名： 未配置决定人时写路径关闭（返回 403 并说明如何开启）， 后台不会自行借用某个身份替人做决定。

边缘发布台账

七态发布（DRAFT → SCHEMA_FROZEN → CALIBRATED → SHADOW → APPROVED → ACTIVE → REVOKED）。 规则：只能相邻推进一格；非终态可直接撤销到 REVOKED； REVOKED 是终态。界面只列出合法下一步，真正把关在后端。

UNKNOWN 对账（收敛记录）

UNKNOWN 的含义是结果未知，必须查状态——不能换键重发、不能直接补偿。 这里显示查了什么、源系统怎么说、允许做什么、禁止做什么。 没有收敛记录时如实说明「尚未进入对账」，而不是当成错误。
